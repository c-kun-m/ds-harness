# 00｜产品目标、范围与完成定义

> 模块编号：M00
> 功能前缀：`PRD`
> 优先级：P0
> 上游基线：以 `01-技术基线与上游锁定.md` 和 `upstream.lock.json` 为准

## 1. 模块目标

本文件定义整个项目的产品合同：我们要交付什么、为谁交付、首版包含什么、明确不包含什么，以及什么证据足以证明产品已经完成。后续架构和实现不得通过缩小范围来制造“完成”的假象。

产品目标是构建一个可安装、可升级、可恢复、可诊断的 DeepSeek Harness 桌面客户端。用户在完全自定义的 Electron + Vue 界面中管理工作区和会话，进行流式 Agent 对话、审批、工具检查、Subagent 和 Goal 操作；真正的 Agent 执行、Session Journal 和 Workspace 业务逻辑仍由官方 DeepSeek Harness 本机服务负责。

## 2. 成功结果

### 2.1 用户结果

- 用户不需要打开终端或官方 Web 页面即可启动和使用 Harness。
- 用户可以在一个稳定的桌面工作台中完成从 Workspace 创建到长期 Session 恢复的闭环。
- 流式内容、Reasoning、Tool、Approval、Question、Subagent 等语义不会被自定义 UI 丢失或误解。
- 应用、页面或 Bridge 崩溃不会静默丢失已经由 Harness 持久化的数据。
- 用户可以清楚区分“尚未提交”“提交中”“执行中”“已完成”“失败”和“结果未知”。
- 用户可以查看当前 App/Harness 版本、诊断问题、安全升级并在升级失败时回滚。

### 2.2 工程结果

- 官方 Harness 的 alpha 变化被限制在 Utility Process 内的版本化兼容层。
- Renderer 保持纯 Web 安全模型，不包含 Node、Electron、Harness Secret 或官方 alpha 类型。
- 所有 V1 功能都有全局功能 ID、实现、测试、性能、安全和验收证据。
- Runtime 与 Client 版本原子锁步，不能组成未经验证的混合版本。
- Windows 上正常退出、Main 崩溃和更新退出均不会遗留 Harness/Tool 子进程。

## 3. 用户与核心场景

| 用户角色 | 主要目标 | 必须保障的体验 |
|---|---|---|
| 日常开发者 | 在本地代码库中使用 Harness 完成复杂开发任务 | 快速启动、清晰流式过程、Tool 可检查、取消可靠、会话可恢复 |
| 高级用户 | 管理多个 Workspace、Session、模型、Queue、Subagent 和 Goal | 高信息密度、键盘操作、状态准确、长会话不卡顿 |
| 安全敏感用户 | 确保模型输出、工具内容和凭据不会获得桌面任意权限 | 安全边界可解释、Secret 不进页面、外链和文件能力受控 |
| 支持与运维人员 | 定位启动、连接、性能、更新和数据问题 | 脱敏日志、诊断包、版本清单、明确恢复步骤 |
| 发布负责人 | 生成可验证、可签名、可回滚的发行版 | Release Set 锁定、SBOM、升级验证、分通道灰度 |

## 4. 范围

### 4.1 V1 必须交付

1. Windows x64 可签名安装包、卸载和升级。
2. 自动发现并启动应用内置的官方 Harness Runtime。
3. 认证交换、HTTP Unary 和 WebSocket Multiplex Stream。
4. Workspace 创建、列表、重命名、排序和删除。
5. Session 创建、搜索、切换、重命名、Fork、排序和归档。
6. 模型目录、Provider 状态和模型选择。
7. Prompt、本地回显、Queue、取消和执行状态。
8. 文本、Reasoning、错误、Tool call/result 的完整实时展示。
9. 历史分页、断线修复、长会话虚拟化和阅读位置恢复。
10. 文本、文件和图片附件；Skills 与文件引用查询。
11. Approval 和 User Question。
12. Tool Presenter、Generic Tool、Shell Transcript、File、Search、Diff 和 Inspector。
13. Subagent 和 Goal 管理。
14. Harness Settings、Credential 状态、Plugin Inventory 只读信息。
15. Light/Dark/System、中文/英文、键盘、无障碍和 reduced-motion。
16. 结构化日志、诊断包、崩溃恢复、更新前备份、失败回滚。
17. 单元、合同、差分、E2E、安全、性能、长稳和升级测试。

### 4.2 V1 非范围

- 不连接用户输入的远程 Harness URL，不暴露 LAN 监听。
- 不加载或嵌入官方 React Web UI。
- 不把官方 Client React 组件移植为 Vue。
- 不允许第三方任意 JavaScript 在 Renderer 内执行。
- 不提供完整交互式 PTY；V1 的 Shell 以安全 transcript 展示为主。
- 不支持多个应用实例或多个窗口争抢同一 Approval。
- 不重写 Harness Agent Runtime、Session Persistence、Tool Runtime 或 Workspace Controller。
- 不将当前 `packages/kernel` 作为生产桌面依赖。
- 不自动追随上游 master，不对不匹配版本进行“尽量兼容”。
- V1 不承诺 Windows ARM64、macOS Intel、Linux ARM64。

### 4.3 后续候选范围

- 正式的 Harness Desktop Profile 和 framed IPC transport。
- macOS ARM64 与 Linux x64 GA 支持。
- 受签名/声明式约束的第三方 Tool Presenter。
- 多窗口只读会话、独立 Inspector 窗口。
- 完整 PTY、远程托管模式、企业策略与集中更新。

后续候选必须使用 P3 功能 ID，不得提前侵入 V1 的安全与协议边界。

## 7. 产品状态与数据模型

### 7.1 产品可见运行状态

```ts
type ProductAvailability =
  | { kind: "BOOTING"; stage: "VERIFYING" | "STARTING" | "AUTHENTICATING" | "SYNCHRONIZING" }
  | { kind: "READY" }
  | { kind: "DEGRADED"; reason: string; retryable: boolean }
  | { kind: "RECOVERY_REQUIRED"; reason: string; actions: string[] }
  | { kind: "UPDATE_REQUIRED"; current: string; required: string }
  | { kind: "FATAL"; supportCode: string };
```

界面只能在 `READY` 后开放会产生业务写入的动作。`DEGRADED` 不得伪装成在线；仍可阅读的本地快照必须标记其同步时间和只读状态。

### 7.2 功能完成记录

```ts
type CompletionEvidence = {
  featureId: string;
  releaseSet: string;
  implementation: { commit: string; paths: string[] };
  automatedTests: { command: string; report: string }[];
  manualAcceptance: { scenario: string; result: "PASS" | "FAIL"; artifact: string }[];
  securityReview?: string;
  performanceReport?: string;
  exceptions: string[];
};
```

只有 Evidence 完整且没有未批准例外时，功能才可以从 `IMPLEMENTED` 进入 `VERIFIED`。

### 7.3 发布成熟度状态

```text
SPIKE → FOUNDATION → INTERNAL_ALPHA → FEATURE_BETA → RC → GA
```

- `SPIKE`：证明官方协议、投影和 Windows 生命周期可用。
- `FOUNDATION`：进程、安全和公共合同稳定。
- `INTERNAL_ALPHA`：最小业务旅程闭环。
- `FEATURE_BETA`：V1 用户功能全部实现。
- `RC`：安全、性能、恢复、安装和升级门禁全部通过。
- `GA`：完成灰度观察并满足质量指标。

## 9. V1 关键用户旅程

### J01：首次启动到第一条回复

1. 安装并启动应用。
2. 应用验证并启动官方 Harness。
3. 用户看到清晰的启动阶段，不看到 Token 或终端窗口。
4. 用户选择/创建 Workspace。
5. 用户创建 Session，选择模型并提交 Prompt。
6. UI 立即显示本地回显，随后展示流式 Reasoning、文本和 Tool。
7. 完成后显示最终状态和耗时。

失败分支必须覆盖 Runtime 损坏、Provider 未配置、认证失败、模型不可用、发送结果未知和 Harness 崩溃。

### J02：长会话继续工作

1. 打开包含 1,000 Turn 的 Session。
2. 默认定位合理位置，虚拟列表不挂载全部节点。
3. 用户上滚加载更早历史，视口不跳动。
4. 新流式事件到达时，用户脱离尾部则不抢夺滚动。
5. 用户重启应用后恢复 Session 和阅读锚点。

### J03：审批与问题

1. Harness 发出 Approval 或 User Question。
2. 用户看到来源、参数、风险、选项和当前 Session。
3. 用户只可提交一次；提交中禁用重复操作。
4. 请求过期或跨 generation 后，旧对话框自动失效。
5. 断线导致结果未知时，不自动重复批准。

### J04：崩溃和恢复

1. Harness 正在流式运行时，分别模拟 Renderer、Bridge 和 Harness 崩溃。
2. 用户看到对应状态，而不是静默冻结。
3. 系统建立新 generation，重新获取 Snapshot 并修复 Gap。
4. 不确定写操作被明确标识。
5. 重复或旧事件不进入新 UI。

### J05：安全升级和回滚

1. 应用检测到签名 Release Set。
2. 更新前停止新写操作并 drain 当前任务。
3. 复制数据到 staging 并用新 Runtime 预检。
4. 预检成功后原子切换；失败时保留旧版本。
5. 新版本启动失败自动进入回滚流程。
6. 旧 Runtime 不得打开已升级的数据副本。

## 10. 非功能完成指标

| 类别 | GA 门槛 |
|---|---|
| 启动 | 托管 Harness 启动成功率 ≥ 99.5%；Crash-free launch ≥ 99.8% |
| 流式 | Harness event 到可见 Tail p95 ≤ 100ms；本地回显 p95 ≤ 16.7ms |
| 滚动 | 交互帧 p95 ≤ 16.7ms；prepend 锚点误差 ≤ 2px |
| 规模 | 1,000 Turn / 25k Event 时顶层挂载节点 ≤ 160 |
| 稳定 | 8–24 小时 soak 无持续 Listener、Worker、Socket 或内存增长 |
| 内存 | 强制 GC 后相对稳定基线增长 ≤ 15%，具体绝对基线由目标机实测冻结 |
| 安全 | P0/P1 安全缺陷为零；Token/Cookie/API Key 泄漏为零 |
| 进程 | 正常退出、Main 崩溃、更新退出均无孤儿进程 |
| 数据 | 已确认持久化数据丢失为零；升级失败可以回滚 |
| 更新 | 签名更新成功率 ≥ 99.5%；Manifest、制品和安装内容一致 |
| 无障碍 | 关键旅程通过键盘、NVDA、200% Zoom；严重 axe 问题为零 |

| 5 RC | 安全、性能、诊断、签名、升级、回滚 | P0/P1 缺陷为零；发布门禁全部通过 |
| 6 GA | 灰度与运行观察 | Internal/Beta 数据满足本文件指标，Completion Audit 通过 |

## 12. 完成定义

### 12.1 单项功能完成

一项功能只有同时满足以下条件才算完成：

- 功能 ID、用户行为和边界已批准。
- 实现位于正确进程和模块，没有绕过公共合同。
- 正常路径、错误路径、恢复路径都有自动测试。
- 涉及权限、Secret、外部内容或写操作时完成安全测试。
- 涉及流式、长列表或大输出时达到性能预算。
- 文档、错误文案、i18n 和无障碍状态同步完成。
- 代码已经通过 Review 和正常 Git Hook。
- Evidence 指向实际 Commit、测试报告和验收 Artifact。

### 12.2 模块完成

- 模块内所有 P0/P1/P2 功能均 `VERIFIED`。
- Public Contract 有版本、Schema、兼容测试和消费者测试。
- 模块拥有、创建的资源均能在关闭/崩溃路径释放或回收。
- 已完成容量、超时、重试、幂等和故障注入测试。
- 没有未登记的 TODO、私有上游导入或安全例外。

### 12.3 产品完成

- `03-全量功能清单.md` 所有 V1 条目均有完成证据。
- J01–J05 全部在签名候选制品和干净 VM 上通过。
- 非功能完成指标全部达标。
- 安装、升级、回滚、卸载、数据恢复、诊断导出全部验证。
- Release Set、SBOM、第三方许可证、签名和 Release Notes 齐全。
- Beta 观察期没有未解决 P0/P1 问题。
