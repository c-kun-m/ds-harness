# 03｜全量功能清单

> 文档性质：V1 功能范围唯一总账
> 状态：`BASELINE-DRAFT`
> 完成规则：清单条目存在不代表完成；必须在功能追踪矩阵中有实现、测试和验收证据

## 1. 目标

本文件列出桌面 UI 项目的所有全局功能 ID、优先级、用户行为、实现边界、错误/安全重点和验证出口。它用于防止开发过程中只完成页面主路径而遗漏协议、失败、取消、恢复、安全、性能、更新和运维能力。

使用规则：

1. 开发前从本文件选择一个功能 ID，并阅读其责任模块文档。
2. 一个提交可以完成一个紧密内聚的功能 ID，不能用同一提交混合多个无关模块。
3. 新增功能先登记 ID、优先级和责任文档，再写代码。
4. 删除功能保留 ID，标记 `REMOVED` 并记录范围变更批准。
5. `P0/P1/P2` 均属于 V1 完成审计；`P3` 是明确后续范围。
6. 同一能力出现在多处时只有一个主 ID，其余模块通过依赖引用，不复制另一套状态机。

## 4. 适用于每一个功能 ID 的强制合同

下方表格会写出每项功能的特殊要求；除此之外，每项功能都必须满足以下通用要求：

| 维度 | 强制要求 |
|---|---|
| 用户行为 | Loading、Empty、Ready、Disabled、Submitting、Success、Error、Offline/Degraded 均有确定行为；条件性能力有明确不可用原因 |
| 实现 | 代码位于责任进程；Harness 业务以官方 Controller/Remote 为真源；Renderer 仅消费 Desktop DTO/Patch |
| 接口 | Command/Event/DTO 有运行时 Schema、协议版本、Capability、deadline、大小上限；流数据带 generation/revision |
| 错误恢复 | 区分未开始、拒绝、取消、失败、结果未知；非幂等写操作不盲目重放；可恢复项给出明确动作 |
| 安全 | 所有跨边界输入不可信；无 raw IPC/HTML/路径/URL；Secret 不进 Renderer、日志和诊断包 |
| 测试 | 至少包含正常、空态、错误、取消/过期、断线/恢复、非法输入、资源释放；涉及流式/长列表时包含性能 |
| DoD | 代码、Review、自动测试、手工验收、i18n、a11y、日志/指标、文档和证据齐全；正常 Hook 通过 |

表中“验证/DoD”是在上述通用合同之外最关键的专项出口。

## 15. 全局开发顺序

```text
PRD / BASE
→ ARCH / ENG
→ ELM / HRS
→ BRG
→ WS / SES / CP
→ VUE
→ CONV / COMP
→ TOOL / INT / SUB / GOAL
→ SET / CRED / DS / GSAP / I18N / A11Y
→ SEC / OBS / REC（从第一阶段同步建设，末期完成全量门禁）
→ TEST / PERF（从第一阶段同步建设，持续阻断回归）
→ PKG / UPD
→ Internal → Beta → RC → GA
```

其中 SEC/OBS/REC/TEST/PERF 不能真的等到业务完成后再开始；箭头表示它们最终验收依赖完整产品，而其测试夹具、日志脱敏和性能基线从 Phase 0/1 就必须进入主线。
