# 04｜工程骨架与公共合同

> 模块编号：M04
> 功能前缀：`ENG`
> 优先级：P0
> 前置：`00` 产品范围、`01` 技术基线、`02` 进程边界、`03` 全量功能清单

## 1. 模块目标

建立桌面项目可以持续开发的工程骨架，并定义 Main、Preload、Bridge、Renderer 之间唯一合法的公共合同。该模块完成后，后续业务功能应当只需要增加受版本控制的命令、DTO、Snapshot/Patch 和实现，不再自行发明 IPC、错误、版本、取消或资源管理方式。

核心结果：

- Main、Preload、Bridge、Renderer 四个目标可独立构建、测试和打包。
- `desktop-contracts` 是跨进程数据唯一真源，不依赖 Electron、Vue 或 Harness。
- 所有边界输入和输出都做运行时 Schema 校验。
- 每条消息可关联、可取消、可限额、可识别旧 generation 和 revision gap。
- Renderer bundle 不含 Node、Electron、DSH、Cordis 或 Secret。
- CI 可以自动阻止越界依赖、协议破坏、Lockfile 漂移和缺失测试。

## 2. 范围与非范围

### 2.1 范围

- pnpm Workspace 的桌面目录和包边界。
- TypeScript project references、构建目标和输出结构。
- Desktop Protocol 的版本、Envelope、Command、Reply、Event、Snapshot、Patch。
- Capability、Limit、Error、Cancellation、Deadline、Trace 和 Resync 合同。
- Runtime Schema、代码生成、兼容策略和测试夹具。
- 配置分层、特性开关、依赖边界和 CI 门禁。
- 模块生命周期、资源释放和测试证据约定。

### 2.2 非范围

- 不实现具体 Harness HTTP/WS transport。
- 不实现 Workspace/Session/Conversation 业务逻辑。
- 不在公共包中引入官方 DSH 类型、Electron 对象或 Vue 响应对象。
- 不提供通用 `invoke(method: string, payload: any)`。
- 不通过共享 Node 内存、remote module 或全局对象绕过合同。
- 不把大附件或无限输出整体塞进单个 IPC Frame。

## 5. Workspace 和构建结构

### 5.1 四个目标

| 目标 | Runtime | 输出 | 必须排除 |
|---|---|---|---|
| Main | Electron Node | CJS/ESM 由 Electron 基线决定 | Vue、官方 Client、Renderer assets 内联 Secret |
| Preload | Electron sandbox preload | 单一最小 Bundle | Node polyfill、动态 require、官方 Client |
| Bridge | Electron Utility Node 环境 | 独立 Bundle/entry | Vue、BrowserWindow、任意 Renderer 组件 |
| Renderer | Chromium | 静态 JS/CSS/Worker | Electron、Node builtin、DSH、Cordis、网络配置和 Secret |

四个目标使用独立 `tsconfig` 和 bundle analyzer。禁止通过别名让一个目标偷偷引用另一个目标的 `src`；共享代码必须进入有明确依赖规则的 package。

### 5.2 建议根命令

```text
pnpm ui:dev                 # 仅开发，仍使用受控进程边界
pnpm ui:build               # 构建四目标
pnpm ui:typecheck           # project references 全量检查
pnpm ui:lint                # lint + boundary
pnpm ui:test                # unit + component + contract
pnpm ui:test:integration    # Bridge/Fake/Real Host
pnpm ui:test:e2e            # Electron E2E
pnpm ui:verify              # 合并门禁聚合
pnpm ui:package             # 未签名候选包
```

实际脚本必须使用本仓库真实命令实现；文档中的名字不能作为未实现命令的完成证据。

## 6. 公共协议总模型

### 6.1 协议版本

```ts
type ProtocolVersion = {
  major: number; // 不兼容变化
  minor: number; // 向后兼容新增
};

const UI_PROTOCOL_VERSION = { major: 1, minor: 0 } as const;
```

- Major 不一致：拒绝建立 Desktop Port，显示更新/恢复页面。
- Bridge minor 更高：只能使用双方能力交集。
- Renderer minor 更高：缺失的 P0/P1 Capability 必须阻止进入 Ready。
- 同一安装包内出现不一致通常代表损坏制品，不能自动降级。

### 6.2 通用 Envelope

```ts
type EnvelopeBase = {
  protocol: ProtocolVersion;
  appInstanceId: string;
  generation: number;
  sequence: number;
  sentAtMonotonicMs: number;
  correlationId: string;
};

type RequestEnvelope<T extends DesktopCommand> = EnvelopeBase & {
  kind: "request";
  requestId: string;
  deadlineMs: number;
  command: T;
};

type ResponseEnvelope<T> = EnvelopeBase & {
  kind: "response";
  requestId: string;
  result: { ok: true; value: T } | { ok: false; error: DesktopErrorDto };
};

type EventEnvelope<T extends DesktopEvent> = EnvelopeBase & {
  kind: "event";
  topic: T["type"];
  event: T;
};
```

所有 ID 使用无语义随机 ID；不能包含用户名、Workspace path、Prompt 或 Secret。`sentAtMonotonicMs` 用于性能，不用于跨进程绝对时间排序。

### 6.3 命令联合

```ts
type DesktopCommand =
  | RuntimeCommand
  | WorkspaceCommand
  | SessionCommand
  | ConversationCommand
  | InteractionCommand
  | SubagentCommand
  | GoalCommand
  | CatalogCommand
  | SettingsCommand
  | SystemIntentCommand
  | UpdateCommand
  | DiagnosticsCommand;
```

示例：

```ts
type SessionPromptCommand = {
  type: "session.prompt";
  sessionId: string;
  clientCommandId: string;
  delivery: "queue" | "steer";
  content: ComposerContentDto;
  expectedSessionRevision?: number;
};
```

每个命令都必须回答：是否幂等、超时是否只取消等待、是否允许 Retry、需要什么 Capability、最大 Payload、多长 Deadline、成功由 Reply 还是后续 durable event 确认。

### 6.4 Snapshot 和 Patch

```ts
type DomainSnapshot<T> = {
  domain: "workspace" | "session" | "conversation" | "interaction" | "settings";
  generation: number;
  revision: number;
  capturedAt: string;
  value: T;
};

type DomainPatch<TOperation> = {
  domain: DomainSnapshot<unknown>["domain"];
  generation: number;
  fromRevision: number;
  toRevision: number;
  operations: TOperation[];
};
```

Patch 应用规则：

1. generation 必须等于当前 generation。
2. `fromRevision` 必须等于 Renderer 当前 revision。
3. Operations 必须在一次浅状态提交中原子应用。
4. 任一校验失败不得“尽力应用”，而是发送 `control.resync`。
5. Snapshot 替换后清理该领域所有旧 Patch、临时交互和过期 Worker 结果。

### 6.5 Capability

```ts
type CapabilityDescriptor = {
  id: string;
  version: number;
  available: boolean;
  unavailableReason?: "UPSTREAM_MISSING" | "POLICY_DISABLED" | "PLATFORM_UNSUPPORTED" | "NOT_READY";
  limits?: Record<string, number>;
};

type CapabilitySnapshot = {
  releaseSetId: string;
  generation: number;
  capabilities: CapabilityDescriptor[];
};
```

UI 必须按 Capability 决定动作是否存在或可用；不能仅用 Harness version 字符串推断。

## 7. 稳定错误模型

```ts
type DesktopErrorDto = {
  code: DesktopErrorCode;
  messageKey: string;
  severity: "info" | "warning" | "error" | "fatal";
  retryability: "NEVER" | "SAFE" | "AFTER_RESYNC" | "USER_CONFIRMATION";
  operationState: "NOT_STARTED" | "REJECTED" | "CANCELLED" | "FAILED" | "OUTCOME_UNKNOWN";
  supportCode: string;
  safeDetails?: Record<string, string | number | boolean>;
};
```

最低错误类别：

| 代码族 | 示例 | 默认恢复 |
|---|---|---|
| `VALIDATION_*` | 非法 DTO、超过限额 | 拒绝；开发环境记录 Schema path |
| `CAPABILITY_*` | 能力不存在/策略关闭 | 重新获取 Capability 或提示不支持 |
| `AUTH_*` | Token/Cookie/authority 失败 | 重启受管连接，不显示 Secret |
| `TRANSPORT_*` | 超时、断线、半开 | 根据幂等性重连或 Outcome Unknown |
| `PROTOCOL_*` | major/fingerprint/revision 错误 | 阻断或 Resync，不尽力兼容 |
| `RUNTIME_*` | 制品、启动、退出、Crash Loop | Repair/Recovery Mode |
| `DOMAIN_*` | Workspace/Session/Interaction 业务拒绝 | 以官方状态刷新并显示具体动作 |
| `SECURITY_*` | sender、路径、URL、签名拒绝 | Fail closed，记录脱敏审计事件 |
| `RESOURCE_*` | Queue、Memory、Disk、Worker 超限 | 降级、释放、Resync 或要求用户处理 |
| `UPDATE_*` | 下载、验证、迁移、回滚 | 保留旧版本并进入恢复流程 |

禁止把原始 Error、stack、HTTP response body 或上游对象传给 Renderer。`messageKey` 由 Renderer 本地化，`safeDetails` 只接受显式白名单字段。

## 8. 限额、取消和流控合同

### 8.1 限额

初始值作为安全默认，性能 Spike 后通过 ADR 固定：

```ts
type ContractLimits = {
  maxControlFrameBytes: 256 * 1024;
  streamChunkBytes: 64 * 1024;
  maxQueuedFramesPerConsumer: 512;
  maxQueuedBytesPerConsumer: 2 * 1024 * 1024;
  maxOperationsPerPatch: 512;
  maxStringBytes: 1 * 1024 * 1024;
  maxObjectDepth: 32;
  maxArrayItems: 10_000;
};
```

大内容使用受限分块、对象句柄或 Inspector 分页；不能通过提高单帧上限逃避流控设计。

### 8.2 取消语义

| 类型 | 语义 |
|---|---|
| `request.cancelWait` | 只让调用者停止等待，不推断远端业务已取消 |
| `session.cancelTurn` | 调用官方 Session cancel，最终由官方状态确认 |
| `stream.unsubscribe` | 停止当前消费者流，不删除 Session |
| `worker.cancel` | 取消本地渲染任务，晚到结果按 epoch/revision 丢弃 |
| `update.cancelDownload` | 仅在安装前取消可恢复下载 |

### 8.3 流控

- Consumer 通过 credit 声明可接收帧数和字节。
- Producer 超过高水位时合并同一未完成文本块的 delta。
- 最终状态、错误和 Interaction 不得丢弃。
- 队列无法安全压缩时清空增量并发送 `RESYNC_REQUIRED`。
- 每个 Session 和全局都要有独立上限，避免单会话饿死全部 UI。

## 9. 配置与 Feature Flag

```ts
type DesktopConfig = {
  environment: "development" | "test" | "production";
  releaseChannel: "internal" | "beta" | "stable";
  paths: { userData: string; logs: string; runtime: string; backups: string };
  limits: ContractLimits;
  features: Record<string, boolean>;
};
```

- 默认值由签名 App 提供。
- 系统策略和用户设置只能覆盖明确字段。
- 生产环境禁止通过环境变量替换 Runtime 路径、更新源、CSP 或远程 Host。
- Flag 不能绕过 Capability、授权、安全检查或迁移。
- 删除 Flag 时同时删除死代码和测试分支，不永久积累。

## 11. 公共 API 设计要求

### 11.1 Preload facade 示例

```ts
type DesktopApi = {
  lifecycle: {
    getSnapshot(): Promise<DesktopLifecycleDto>;
    subscribe(listener: (event: DesktopLifecycleEvent) => void): () => void;
  };
  workspace: {
    getSnapshot(): Promise<WorkspaceSnapshotDto>;
    create(input: WorkspaceCreateInput): Promise<CommandReceiptDto>;
    rename(input: WorkspaceRenameInput): Promise<CommandReceiptDto>;
  };
  session: {
    prompt(input: SessionPromptInput): Promise<CommandReceiptDto>;
    cancelTurn(input: CancelTurnInput): Promise<CommandReceiptDto>;
  };
  conversation: {
    getSnapshot(sessionId: string): Promise<ConversationSnapshotDto>;
    subscribe(sessionId: string, listener: (patch: ConversationPatchDto) => void): () => void;
  };
  system: {
    pickFiles(input: PickFilesInput): Promise<FileHandleDto[]>;
    openExternal(input: OpenExternalInput): Promise<void>;
  };
};
```

真实 API 应继续按领域拆文件，并由 Schema 和类型共同生成；示例不是批准全部参数的替代。

### 11.2 DTO 规则

- 仅 JSON/structured-clone 安全基础类型和经过批准的二进制句柄。
- 时间使用 ISO UTC 字符串；持续时间使用整数毫秒。
- 金额/大整数如果未来出现，使用带单位的字符串，不依赖 JS 浮点猜测。
- Map/Set 转换为数组或 Record；Error 转 DesktopErrorDto。
- 文件使用 opaque handle + displayName + capability，不暴露无必要绝对路径。
- Rich content 使用封闭 node union，不传已渲染 HTML。
- 所有集合定义排序、去重、最大数量和分页语义。

### 11.3 兼容规则

- 加可选字段：minor 版本增加，旧消费者必须忽略未知字段。
- 加必填字段、改变语义或删除 union member：major 版本增加。
- 事件重命名不是兼容变化；使用新事件并提供迁移期。
- Patch operation 必须是封闭联合；未知 operation 触发 Resync/升级，不跳过。
- Desktop Protocol 兼容不代表 Harness Protocol 兼容；后者由 Release Set 锁定。

## 12. 测试与 CI 分层

| 层 | 内容 | 最低要求 |
|---|---|---|
| Schema Unit | 每个 command/reply/event/dto/error | 成功、缺字段、错类型、超限、未知 type |
| Property | Envelope、Patch reducer、Redactor、Limits | 重复、乱序、任意嵌套和边界数值 |
| Consumer Contract | Preload/Bridge/Renderer/Main | 同一 golden 在所有消费者一致解析 |
| Boundary | Import graph、bundle content | 每个禁止边都有负向 fixture |
| Integration | MessagePort、Native IPC、Fake Harness | 超时、取消、断线、背压、重建 |
| Compatibility | protocol major/minor、old/new consumer | 批准矩阵全部通过 |
| Package | exports、types、license、tree-shaking | 不可从公共入口访问私有实现 |
| Clean Build | Windows 干净环境 | frozen install、typecheck、test、build、package |

## 13. 开发顺序

1. 建立 `apps/desktop` 和四目标最小 entry，暂不接业务。
2. 建立 `desktop-contracts`、ProtocolVersion 和 Envelope Schema。
3. 建立 DesktopError、Capability、Limits、Snapshot/Patch。
4. 建立无 Vue 的 Desktop Port request/response/subscribe 客户端。
5. 建立 Preload facade 和 Native Intent 骨架。
6. 建立独立 Bridge entry 和 Fake Bridge 回显测试。
7. 建立 generation/revision、cancel、deadline、credit/ack/resync。
8. 建立 imports/bundle 依赖边界门禁。
9. 建立 fixture、property test 和 old/new compatibility suite。
10. 接入 CI、clean build、Artifact manifest 和 trace evidence。
11. 通过 Foundation Exit Gate 后再允许业务模块增加 Command。

## 14. Foundation Exit Gate

- 四个目标能在干净 Windows 环境独立构建和启动。
- Renderer bundle scan 不含 Node、Electron、官方 DSH、Cordis 或 Secret。
- 未知/畸形/超限 Frame 在 Preload 和 Bridge 两侧均被拒绝。
- Protocol major 不匹配不能进入 Ready。
- generation/revision 错误能稳定触发丢弃或 Resync。
- 慢消费者不会导致无界 Queue。
- 非幂等命令的超时不会触发自动重放。
- 所有资源可以显式、幂等释放。
- 合同 Golden 和至少一组 old/new 消费者测试通过。
- CI 能主动阻断 Lockfile 漂移、越界导入、Schema 破坏和 Secret fixture。

- [ ] 静态依赖和 Bundle 门禁可证明 Renderer 没有官方包。

- [ ] Foundation Exit Gate 可由实际命令和 Artifact 证明。
