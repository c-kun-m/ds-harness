# 14：安全、可观测性与故障恢复

## 1. 文档目标

本文件定义桌面客户端从开发阶段就必须实现的安全、日志、指标、诊断和故障恢复能力。它们不是上线前补做的“非功能需求”，而是所有业务模块共同依赖的基础设施。

本模块的完成定义是：任何来自 Renderer、模型输出、工具输出、工作区文件、Harness 进程或更新包的数据都按不可信输入处理；任一进程发生异常时，系统能给出确定状态、保护数据、回收资源，并向用户提供可执行的恢复动作。

## 2. 固定信任边界

| 区域 | 权限 | 可以持有 | 禁止持有 |
|---|---|---|---|
| Electron Main | 系统高权限 | 窗口、更新、Runtime 路径、短期启动 Token、系统凭据引用 | Session 业务状态、完整 Prompt/Response 日志 |
| Preload | 最小桥接权限 | 固定 API 函数、当前页面 MessagePort | 原始 `ipcRenderer`、文件系统、任意命令接口 |
| Bridge Utility | Harness 客户端权限 | Cookie、官方 Client、Controller、会话投影、稳定 DTO | Electron BrowserWindow 管理权限、任意系统 Shell |
| Vue Renderer | 不可信展示层 | 版本化 DTO/Patch、界面偏好、草稿 | Node API、官方 Harness 包、Token、Cookie、API Key、任意网络 |
| Harness Sidecar | Agent Runtime 权限 | Harness Home、Session、Tool/Agent 运行状态 | Electron 页面对象和用户桌面凭据库 |
| Updater | 受签名发布权限 | 下载中的签名制品、版本清单 | 运行时 Session 内容、未签名可执行文件 |

新增跨边界的数据通道前，必须在本表和威胁模型中登记身份、Schema、容量上限、取消方式、日志策略和失败语义。

## 4. 安全功能规格

### SEC-001：威胁模型与数据流登记

**用户行为**：此功能无直接页面入口，但用户使用任意功能时都受到同一安全边界保护。

**实现方式**：

1. 为 Main、Preload、Bridge、Renderer、Harness、文件系统、Keychain、Updater 绘制数据流图。
2. 每条边登记调用方、接收方、身份校验、Schema、最大字节数、超时、取消、日志字段和残余风险。
3. 威胁至少覆盖 STRIDE、XSS、IPC 注入、路径穿越、符号链接绕过、Token 泄漏、更新劫持、恶意 Tool 输出和供应链替换。
4. 新能力必须先更新威胁模型，再创建代码接口。

**失败与恢复**：缺少 Owner、容量边界或攻击测试的通道不得合并；不能以“仅本机使用”作为免除认证或校验的理由。

**测试与 DoD**：每项高风险威胁都有防护、自动化攻击用例、责任模块和已接受的残余风险；安全评审记录可追溯到具体功能 ID。

### SEC-002：Electron 安全策略

**实现方式**：

- BrowserWindow 固定 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`、`webviewTag: false`、`webSecurity: true`。
- 只加载 `app://desktop/`；禁止 `file://`、远程 JavaScript、`unsafe-eval` 和任意页面导航。
- Renderer CSP 从 `default-src 'none'` 开始，`connect-src 'none'`，仅按构建产物实际需求增加最小来源。
- 默认拒绝权限申请、新窗口和主框架导航。
- 构建阶段检查 Electron Fuses：关闭 RunAsNode、NODE_OPTIONS、CLI Inspect；启用 ASAR 完整性和仅从 ASAR 加载应用代码。

**错误处理**：CSP 或权限违规进入结构化安全日志；不向用户显示包含原始 Payload 的错误。

**测试与 DoD**：自动测试读取每个 BrowserWindow 的最终配置；Renderer 中访问 `process`、`require`、Socket、HTTP、WebSocket 均失败；已知危险协议无法导航或打开。

### SEC-003：IPC 身份、Schema 与容量控制

**实现方式**：

- Preload 不提供 `send(channel, payload)`，只提供领域化方法。
- 每个请求包含 `uiProtocolVersion`、`rendererOwnerId`、`connectionGeneration`、`requestId` 和 deadline。
- Main 校验 sender、top frame、窗口类型和 `app://desktop` origin；Bridge 再校验领域 Schema。
- 控制面请求建议上限 256 KiB；大内容使用 64 KiB 分片或文件 Capability。
- 每个 Session 默认缓冲上限 2 MiB；超过高水位时暂停增量并要求 Snapshot Resync。
- 所有请求、响应、事件和错误都必须可 structured-clone，禁止透传 Class、Error、Function、Map 和循环对象。

**错误与恢复**：非法帧返回稳定 `IPC_SCHEMA_INVALID`、`IPC_SENDER_DENIED` 或 `IPC_LIMIT_EXCEEDED`；连续攻击触发窗口级速率限制，但不得阻塞其他合法窗口或 Bridge 停止流程。

**测试与 DoD**：一百万组属性/Fuzz 输入不得造成越权、崩溃或无界分配；关闭页面后其所有 request、stream 和 subscription 均被取消。

### SEC-004：Harness Sidecar 与传输认证

**实现方式**：

- 仅用绝对路径、参数数组和 `shell:false` 启动经过签名及 SHA-256 校验的 Runtime。
- 子进程环境采用白名单，不继承与 Harness 无关的 Secrets 和调试参数。
- 只接受 `127.0.0.1` 与 Supervisor 分配的端口；拒绝重定向、代理和其他 authority。
- 启动 Token 仅用于根路径的一次 Cookie 交换；Cookie 仅保留在 Bridge 内存。
- Renderer、Pinia、localStorage、日志、诊断包和错误详情中不得出现 endpoint secret。
- V1 关闭外部/远程 Harness 模式。

**错误与恢复**：Host、Origin、端口、Runtime Hash 或版本不匹配时 fail closed；认证失败不循环使用同一个 Token，交由 Supervisor 重启受管 Runtime。

**测试与 DoD**：篡改 Runtime、Token、Cookie、Host、Origin、Redirect 和代理设置的用例全部拒绝；Secret canary 扫描所有进程日志结果为零。

### SEC-005：内容、链接和文件安全

**实现方式**：

- Markdown 转 AST 后由 Vue 组件渲染，关闭 raw HTML，禁止 `v-html` 承载模型内容。
- URL 只允许显式协议；外部 HTTPS 交给 Main 二次校验和用户确认。
- 外部图片默认不加载；附件图片验证 MIME、Magic Bytes、尺寸和解码上限。
- ANSI 输出删除 OSC、危险链接和控制序列；Diff/JSON/Tool Meta 设递归深度、节点数和字节上限。
- Renderer 只持有 opaque file handle；Main/Bridge 解析真实路径并校验作用域、TTL、symlink 和最终目标。
- 工作区外文件操作必须有单独能力授权，不能仅凭字符串路径执行。

**错误与恢复**：不安全内容降级成纯文本或受限 Generic Card；文件检查在执行前后都失败时不继续操作，并返回可定位的安全错误码。

**测试与 DoD**：OWASP XSS corpus、恶意 SVG、`javascript:`、双重 URL 编码、ANSI OSC、畸形 Diff、路径穿越和 symlink/TOCTOU 用例均不能执行代码或越权读取。

### SEC-006：凭据生命周期

**用户行为**：用户可以新增、替换、删除和验证 Provider 凭据，但永远不能从界面读回明文。

**实现方式**：

- Renderer 表单值只存在于组件局部变量，提交完成立即覆盖和释放。
- 返回 Renderer 的数据只有 provider ID、masked hint、状态和更新时间。
- Windows 使用 Credential Manager/DPAPI 对应的 OS Keychain；其他平台必须验证安全存储后才能启用持久化。
- 若需要向 Harness 提供密钥，通过受控 credentials provider 或最小环境注入，不能拼入命令行。
- 修改影响 Runtime 的凭据时进入受控重启流程。

**错误与恢复**：安全存储不可用时明确进入 session-only 或拒绝持久化，禁止退化成明文配置文件。

**测试与 DoD**：Secret 不进入 Pinia、Vue DevTools、localStorage、IndexedDB、日志、Crash Dump 和诊断包；读接口永不返回明文。

### SEC-007：供应链与前端扩展策略

**实现方式**：

- 所有依赖使用 frozen lockfile；Harness Runtime、官方 Client 与 compat 必须精确版本锁步。
- 生成 SBOM、第三方许可证、制品 Hash 和构建 provenance。
- 首版 Tool Presenter 只允许编译进应用的第一方模块。
- 未知 Tool 使用 Generic Card；不得从 Harness 动态下载并执行任意 Renderer JavaScript。
- 未来第三方 Presenter 必须使用声明式 UI Schema 或独立沙箱，并另立安全 ADR。

**测试与 DoD**：未锁版本、未批准 install script、未登记许可证、签名错误或 Hash 不匹配都会阻断发布；Fork PR 无法访问签名或发布凭据。

## 5. 可观测性功能规格

### OBS-001：稳定错误模型

统一错误结构：

```text
DesktopError {
  code
  messageKey
  recoverable
  retryPolicy
  correlationId
  safeDetails?
}
```

错误至少分为：配置、兼容、认证、权限、Schema、容量、网络、Harness、取消、超时、数据、更新、未知结果。用户可恢复错误必须提供明确动作，例如重试连接、打开诊断、重新选择目录、更新应用或恢复备份。

**DoD**：启动、认证、重连、写操作、更新和恢复的关键失败不得落入笼统 `UNKNOWN_ERROR`；内部 Stack 和敏感路径不进入 Renderer。

### OBS-002：结构化日志与强制脱敏

**实现方式**：

- Main、Bridge、Harness Supervisor 分流记录 JSONL，字段包含时间、组件、进程、版本、generation、operation、phase、duration、errorCode。
- Readiness Parser 在任何通用 stdout logger 前消费并脱敏 Token 行。
- Redactor 递归处理 Header、Cookie、URL Query、环境变量、Error cause 和嵌套对象。
- 日志建议滚动为 5 个 10 MiB 文件，总上限 50 MiB。
- Prompt、Response、Tool 参数和工作区文件内容默认不记录。

**DoD**：至少十万组包含合成 Token/API Key/Cookie 的随机嵌套数据通过零泄漏测试；Harness 原始 stdout 不直接落盘。

### OBS-003：健康状态与 Supervisor 指标

记录：Runtime/Bridge/Renderer 状态、启动和认证耗时、进程退出码、WS generation、重连次数、流数量、队列长度、丢弃/合并/Resync 次数。

连续 5 分钟内同一组件崩溃 3 次进入 Recovery Mode，停止自动重启并向用户展示诊断和恢复选项。

**DoD**：子进程退出 1 秒内被识别；每次状态转换都记录上一状态、下一状态和原因码。

### OBS-004：Metrics 与 Trace

**实现方式**：

- Histogram：冷启动、Harness ready、RPC、Event-to-Paint、关闭和更新耗时。
- Gauge：IPC backlog、Mounted Rows、Worker、Socket、Timer、Heap。
- Counter：重连、Gap Repair、取消、恢复失败、限额拒绝。
- correlation context 显式穿过 MessagePort；Main/Bridge 进程内可使用 AsyncLocalStorage。
- 禁止把 SessionId、Prompt、路径和 ToolCallId 作为高基数 Metric Label。

**DoD**：每设备 Metric Series 设置硬上限；开启 Metrics 后稳态 CPU 额外开销小于 1%，内存额外开销小于 20 MiB。

### OBS-005：诊断包与崩溃报告

**用户行为**：用户可在故障页或设置页预览并导出诊断包；上传必须明确同意。

**实现方式**：诊断包只包含版本 Manifest、进程状态、脱敏日志、更新记录、资源计数、错误码和 Hash；默认不包含 Transcript、Prompt、Response 和工作区文件。

**DoD**：导出后通过两套独立 Secret Scanner；上传失败不影响本地恢复；用户能在无终端操作的情况下找到错误原因和 correlation ID。

## 6. 故障恢复功能规格

### REC-001：Renderer 崩溃恢复

- Main 和 Harness 保持运行。
- 重新创建安全窗口和 MessagePort。
- 新 renderer owner/generation 请求完整 Workspace、Session 和 Conversation Snapshot。
- 旧页面的请求与 Patch 全部失效。

**DoD**：Renderer 崩溃期间的官方 Session 事件可通过 Snapshot/Gap Repair 恢复；不会重复提交 Prompt 或 Approval。

### REC-002：Bridge 崩溃恢复

- Main 标记 Bridge 为 restarting，暂停新的领域命令。
- 启动新 Utility，重新认证，connection generation 增加。
- 官方 Controller 完成同步屏障后发布 READY 和全量 Snapshot。
- 不自动重放结果未知的写命令。

**DoD**：Bridge 重启不会终止 Harness；旧 response/patch 不能覆盖新状态。

### REC-003：Harness 崩溃恢复

- Bridge 将所有未决操作结算为明确失败或 `OUTCOME_UNKNOWN`。
- Supervisor 按退避策略重启受管 Harness。
- 新 Host 连接完成后重新加载 durable Session；process-local Job 状态不得伪造为仍在运行。
- 超过崩溃阈值进入 Recovery Mode。

**DoD**：不会在不确定状态下重复创建 Session、发送 Prompt 或批准高风险动作。

### REC-004：Main 崩溃与孤儿清理

- stdin lifecycle companion 在父进程消失时触发正常退出。
- Windows Job Object 在正常退出失败时终止完整进程树。
- 下次启动检测未完成更新、残留锁和异常退出标记。

**DoD**：强杀 Main 后 Harness 和其 Tool 子进程在规定时间内消失；下次启动可以安全恢复。

### REC-005：写操作结果未知

状态固定为：

```text
PENDING → CONFIRMED | REJECTED | CANCELED | OUTCOME_UNKNOWN
```

`OUTCOME_UNKNOWN` 不得自动重试。UI 应提示用户刷新服务端状态；创建类操作使用 clientCommandId/rpcId 对账，审批类操作重新获取 interaction 状态后才能再次操作。

### REC-006：Recovery Mode

Recovery Mode 提供：查看版本和状态、重新启动 Harness、导出诊断、选择已验证备份、退出应用。它不得自动删除数据、清空 Harness Home、降级 Runtime 或上传内容。

## 7. 开发顺序

1. SEC-001、SEC-004 与 OBS-002 必须在 Supervisor Spike 前完成。
2. SEC-002、SEC-003 与 OBS-001 在 Electron 骨架阶段完成。
3. OBS-003、REC-001、REC-002、REC-003 与 Bridge 一起开发。
4. SEC-005 与内容渲染、附件、Tool Card 同步开发。
5. SEC-006 与设置/凭据模块同步开发。
6. OBS-004、OBS-005、REC-004～REC-006 在 Alpha 后、Beta 前完成。
7. SEC-007 与发布流水线一起成为 RC 门禁。

## 8. 模块验收清单

- [ ] 每条跨进程通道均在威胁模型登记。
- [ ] Renderer 无 Node、网络、Token、Cookie 和 API Key。
- [ ] 所有 IPC 双向 Schema 校验并具备容量上限。
- [ ] 模型、Tool、Markdown、URL 和文件均作为不可信输入处理。
- [ ] 日志和诊断包 Secret Canary 命中数为零。
- [ ] 所有关键错误都有稳定错误码和恢复动作。
- [ ] Renderer、Bridge、Harness、Main 分别完成崩溃恢复测试。
- [ ] 不确定写操作不会自动重试。
- [ ] Crash Loop 会进入 Recovery Mode，而不是无限重启。
- [ ] 供应链、签名、SBOM 和依赖边界进入 CI 门禁。

## 9. 模块完成定义

本模块只有同时满足以下条件才可标记完成：

1. `SEC-001`～`SEC-007`、`OBS-001`～`OBS-005`、`REC-001`～`REC-006` 均在功能追踪矩阵达到 `VERIFIED`，不存在用模块级测试替代单项证据的情况。
2. Renderer、Bridge、Harness、Main 四类崩溃和启动/更新中断均产生确定状态、稳定错误码、资源清理结果和用户恢复动作。
3. IPC Fuzz、内容攻击语料、路径与符号链接、Runtime 篡改、更新篡改和 Secret Canary 在 Release 构建上全部通过。
4. 日志、指标、Trace、Crash Report 与诊断包满足字段白名单、容量/保留上限和二次脱敏要求；凭据和用户内容泄漏为零。
5. 威胁模型、风险登记、自动测试、人工安全评审和恢复 Runbook 均绑定同一 Release Set，所有 Critical/High 问题关闭。
6. 24 小时 RC 故障/恢复与长稳测试通过，恢复流程不依赖开发工具、手工改数据或删除 Harness Home。
