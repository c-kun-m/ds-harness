# 第二部分：EffectStack 到底是什么

先不考虑插件、Context 和 Fiber。

我们先定义一个最普通的问题：

> 我有一组清理函数，结束时需要从后往前执行。

清理函数可能是：

```ts
() => {
  console.log('删除事件监听器')
}
```

也可能是异步的：

```ts
async () => {
  await database.close()
}
```

所以它的类型是：

```ts
export type Disposer = () => void | Promise<void>
```

拆开理解：

```text
Disposer
    是一个函数
        没有参数
            返回 void
            或者 Promise<void>
```

为什么同时支持同步和异步？

因为不同资源的清理方式不同：

```text
从 Map 删除服务        → 同步
删除事件监听器          → 同步
等待 Worker 结束        → 异步
关闭数据库连接          → 异步
停止子进程              → 异步
```

# 十、先写第 0 版 EffectStack

先只解决两个问题：

1. 保存清理函数。
2. 从后往前执行。

不要现在就考虑重复释放和错误聚合。

```ts
export type Disposer = () => void | Promise<void>

export class EffectStack {
  private readonly disposers: Disposer[] = []

  add(disposer: Disposer): void {
    this.disposers.push(disposer)
  }

  async dispose(): Promise<void> {
    for (
      let index = this.disposers.length - 1;
      index >= 0;
      index -= 1
    ) {
      const disposer = this.disposers[index]

      if (disposer !== undefined) {
        await disposer()
      }
    }
  }
}
```

现在逐行解释。

## `disposers`

```ts
private readonly disposers: Disposer[] = []
```

这是一个数组，专门保存清理函数。

假设执行：

```ts
stack.add(removeLogger)
stack.add(removeListener)
stack.add(stopWorker)
```

数组里就是：

```text
索引 0：removeLogger
索引 1：removeListener
索引 2：stopWorker
```

`private` 表示只有 `EffectStack` 类内部可以直接访问。

`readonly` 表示不能把整个数组替换掉：

```ts
this.disposers = [] // 不允许
```

但仍然可以向数组加入元素：

```ts
this.disposers.push(disposer) // 允许
```

## `add`

```ts
add(disposer: Disposer): void {
  this.disposers.push(disposer)
}
```

这个方法目前只做一件事：

> 把收到的清理函数放到数组最后。

这里不执行清理函数。

注意区别：

```ts
this.disposers.push(disposer)
```

是保存函数。

而：

```ts
disposer()
```

才是执行函数。

## `dispose`

```ts
async dispose(): Promise<void>
```

因为某些清理函数是异步的，所以整个关闭过程也是异步的。

调用方必须：

```ts
await stack.dispose()
```

这样才能确定所有清理都结束了。

## 反向循环

```ts
let index = this.disposers.length - 1
```

假设数组长度是 3，有效索引是：

```text
0、1、2
```

所以最后一项索引是：

```text
3 - 1 = 2
```

每次：

```ts
index -= 1
```

于是访问顺序是：

```text
2 → 1 → 0
```

也就是：

```text
stopWorker
removeListener
removeLogger
```

## 为什么检查 `undefined`

```ts
const disposer = this.disposers[index]

if (disposer !== undefined) {
  await disposer()
}
```

因为我们开启了：

```json
"noUncheckedIndexedAccess": true
```

TypeScript 会认为数组索引可能越界。

所以 `disposer` 类型是：

```ts
Disposer | undefined
```

检查以后，TypeScript 才能确定它一定是函数。

## 为什么 `await` 同时支持同步函数

如果 disposer 返回：

```ts
void
```

`await` 会立即继续。

如果 disposer 返回：

```ts
Promise<void>
```

`await` 会等待 Promise 完成。

因此不需要分别写两套逻辑。

# 十一、第 0 版有什么问题

这个版本能帮助你理解“栈”，但还不能用于生产。

## 问题一：调用两次会清理两次

```ts
await stack.dispose()
await stack.dispose()
```

所有 disposer 都会重复运行。

如果是：

```text
关闭数据库
杀死进程
删除服务
```

重复执行可能报错。

## 问题二：两个地方同时调用会并发清理

```ts
await Promise.all([
  stack.dispose(),
  stack.dispose(),
])
```

两个循环可能同时运行。

## 问题三：一个清理失败，后面的不执行

```ts
await disposer()
```

如果这里抛错，循环立即停止。

其他资源就会泄漏。

## 问题四：开始关闭后仍能添加

```ts
const closing = stack.dispose()

stack.add(newDisposer)

await closing
```

新加入的 disposer 是否会执行，会受到循环当前位置影响，行为不确定。

# 十二、最终版本为什么会逐步增加这些东西

接下来我们会按顺序修复：

```text
第 0 版
数组 + 反向循环
    ↓
第 1 版
每一项只能执行一次
    ↓
第 2 版
整个 Stack 只能关闭一次
    ↓
第 3 版
清理错误统一收集
    ↓
最终版
关闭后禁止继续注册
```

需要增加的字段也不是凭空出现的：

| 字段 | 解决什么问题 |
|---|---|
| `disposers` | 保存清理函数 |
| `EffectEntry.execution` | 保证单个 Effect 只运行一次 |
| `state` | 防止关闭后继续注册 |
| `disposal` | 让重复关闭共享同一个 Promise |
| `errors` | 收集所有清理错误 |

所以不要直接背最终代码。每一个字段都应该对应一个已经看见的问题。
