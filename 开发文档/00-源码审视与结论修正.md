## 已确认的三层架构

### 第一层：Cordis 生命周期内核

Cordis 不只是 disposer 栈。它同时解决：

- 插件实例的状态机和重载；
- 多形态 Effect 的登记、回滚和异步停稳；
- 父子 Fiber 所有权；
- Context 作用域、隔离和服务代理；
- required/optional 依赖变化引发的卸载与恢复；
- Plugin Registry、配置校验和更新；
- 多种事件分发语义。

因此，一个只会“数组逆序执行”的 `EffectStack` 只能覆盖第一个练习，不能代表 Cordis 核心。

### 第二层：DSH Scope 与 Agent Runtime

DSH 在 Cordis 上增加了更适合 Agent 的作用域标签、父链和分层注册，并把 Session、LLM、Tools、Agent Loop 等能力组合成运行时。关键事实包括：

- Session 是仅追加事件真源，模型消息是纯投影；
- 每个模型请求应有可重建的请求信封；
- 工具可见性、策略准入、执行和最终提交是不同阶段；
- 并行安全工具只在执行阶段重叠，结果仍按模型顺序提交；
- Agent 创建先在私有作用域内完成 setup，再原子发布；
- 销毁需要停止循环、排空工作、释放 scope、移除 agent 和 session；
- 权限与沙箱必须 fail-closed；
- 恢复保留已持久化的中断轮次，用合成 closer 明确未知副作用，而不是截断证据。

### 第三层：产品扩展

Todo、Plan、Goal、Jobs、Subagent、Workflow、Skills 和 MCP 都建立在前两层合同之上。它们不是可以随意复制的 UI 功能：每一个都有明确的所有者、事件归属、恢复语义、取消边界和限制。

## 对旧文档的主要修正

| 旧结论 | 新结论 |
|---|---|
| “自研最小插件内核”就足够 | 学习目标改为复刻完整核心行为；最小栈只作为递进练习 |
| MVP 禁止 HMR、自动依赖等待和配置更新 | 这些是 Cordis 核心学习内容，必须在 K11–K12 学习；产品可延迟启用，但不能从内核课程删除 |
| Effect 卸载就是严格全局 LIFO | 单个 Effect 内清理逆序串行；Fiber 的 sibling Effect 在卸载时可以并发等待 |

## Cordis 源码中最容易漏掉的行为

### Effect 不是“回调数组”

- owner wrapper 在 setup 开始前登记，解决 setup 内重入卸载；
- 同步 setup 失败会回滚已经收集的 disposer 并移除 owner；
- async setup 拒绝后也会清理；
- 公开 disposer 单次有效；
- 结构拥有者能加入另一个调用者已经启动的清理；
- Fiber 进入 UNLOADING 后拒绝创建新 Effect；
- async generator 在 epoch 变化后停止接纳新的清理项。

### Fiber 不是“插件状态枚举”

它同时拥有状态、配置解析、依赖 epoch、Effect 容器、子插件、加载惯性、更新和重启。状态至少覆盖 `PENDING`、`LOADING`、`ACTIVE`、`FAILED`、`UNLOADING`、`DISPOSED`，每个转移都和可接受的新工作相关。

### Service 不是“任意属性注入”

代理会追踪服务调用所处 Context，阻止未声明访问，按隔离标签选择 provider，并在 provider 状态变化时通知依赖 Fiber。required 依赖不可用时消费者不应继续带病运行。

## DSH Scope 中最容易漏掉的行为

- `createScope` 背后有一个 Fiber，Scope 释放要等待 Fiber 及其 inertia 完全停稳；
- 父链只能由持有绑定句柄的一方改绑，且拒绝环；
- scoped event 从 child 向 ancestor 可见，不能反向向下泄漏；
- global listener 和 scope target 的过滤组合有明确语义；
- `NamedEntries` 拒绝重复名，旧 undo 只能撤销自己的精确条目；
- `ScopedLayers` 的可见性和生命周期来自同一个 Context；
- action 成功但 notify 失败时必须回滚 action；
- 只读查询不能为了方便偷偷创建空 layer。

## Agent Runtime 中最重要的不变量

1. 模型可见事实可以从持久日志与当前组合重建；
2. 每条工具调用只产生一个权威最终结果；
3. 取消不能把更具体的已知失败伪装成普通 aborted；
4. 工具参数、日志参数和实际执行参数不能静默分叉；
5. Agent、Session、Scope 的发布和拆除是事务边界；
6. 审批无应答者或应答失败时拒绝，不默认允许；
7. 沙箱后端不可用时拒绝运行，不静默转为无限制；
8. durable append 成功返回意味着批次已安全落盘；
9. 压缩改变 Surface，不删除原始日志；
10. 子 Agent、Job、Workflow 的运行由明确句柄拥有，服务卸载不能留下无人负责的活动工作。

## 本体能力的真实位置

固定版本 DSH 没有完整的 OWL/RDF/SHACL/SPARQL 本体规划器，也没有本项目要实现的“事实 → 候选动作 → 前置条件 → 执行 → 后置事实 → 补偿”闭环。因此：

- 13–15 是原创领域层，不是上游翻译；
- 本体候选可以限制模型看到的工具，但执行前仍要再次确定性校验；
- 计划状态必须进入可恢复日志或领域事务，不能只留在 Prompt；
- 事实回写需要幂等键、版本检查和失败补偿；
- Workflow 脚本不能成为权威本体计划存储。

## 最终结论

学习路线必须先把 Cordis/DSH 的生命周期和运行时行为学完整，再在它们提供的稳定边界上做本体扩展。项目可以不复刻 DSH 的所有产品包和 UI，但凡标为“核心复刻”的部分，都必须覆盖状态、错误、并发、重入、取消、所有权、恢复和代表性上游测试；否则只能叫阶段性练习。
