# 源码审视与结论修正

## 审视范围

旧报告基于提交 `99f6f02fecdb`、版本 `0.1.0-rc.7`。当前仓库位于 `D:\project\deepseek\deepseek-harness`，HEAD 为 `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`，版本为 `0.1.1-rc.2`。两者之间有 3319 个文件发生变化，因此旧报告适合用作架构导读，不能继续作为当前版本的精确功能清单。

## 仍然成立的核心判断

- DSH 是插件化 Agent Runtime，不是普通聊天 SDK；当前 [架构文档](../deepseek-harness/docs/architecture.md)仍把 Session、System Prompt、Tools、Agent、Agent Loop 和 LLM 定义为可组合能力。
- Agent Loop 是 Turn/Step 状态机；[当前循环实现](../deepseek-harness/packages/core/agent-loop/src/agent.ts)仍按 `turn/start → step/start → 模型流 → 工具调用 → step/end → turn/end` 记录事件。
- 工具可见性与执行许可是两层控制；[工具运行时](../deepseek-harness/packages/core/tools/src/index.ts)仍包含作用域注册、`pre-execute`、审批、单调 Guard、`execute`、`post-execute` 和结果定稿。
- 并发工具只重叠执行阶段，策略处理和结果按模型顺序提交；证据位于 [tool-calls.ts](../deepseek-harness/packages/core/agent-loop/src/tool-calls.ts)。
- Session 是事件日志，模型可见输入必须能从日志重建；[Session 类型](../deepseek-harness/packages/core/session/src/types.ts)的格式版本当前仍为 `0`。
- Standard、Minimal、Code、Cordis 四个 Preset 当前仍存在；[组装测试](../deepseek-harness/apps/cli/tests/web-agent-presets.e2e.ts)仍验证 Standard 的 25 个工具、Minimal 的两个工具和 Code 的单一 `run_code` 表面。
- Plan Mode 当前仍是软指导，不是强制工具白名单；[Plan README](../deepseek-harness/packages/plan/plan-mode/README.md)明确要求沙箱和审批独立执行硬限制。
- Spawn、Fork、one-shot、continuable、FIFO follow-up 和仅中断当前 Turn 的行为仍成立；[控制工具说明](../deepseek-harness/packages/subagent/tool-subagent-control/README.md)给出了当前语义。
- Workflow 是受限脚本编排，不是持久化通用 DAG 引擎；普通 Subagent 服务也没有优先级边、条件边和补偿边。
- 沙箱的策略词汇只覆盖文件效果，不覆盖网络、凭据、设备和完整系统调用隔离；[沙箱定义](../deepseek-harness/packages/sandbox/sandbox/README.md)仍明确声明这一点。
- 当前源码仍没有 OWL、RDF、SPARQL、SHACL 或本体规划器。除 [mcp-memory 示例](../deepseek-harness/examples/mcp-memory/README.md)的简单知识图谱外，没有本体驱动执行实现。

| “DSH 有 248 个包” | `248` 是旧提交中全部 `package.json` 的数量，其中包含 vendor、apps、examples、native 等，不等于 248 个产品包。当前 HEAD 有 256 个受 Git 跟踪的 `package.json`，其中 `packages/*/*` 下为 234 个。 |

| Goal 自己会自动运行 256 轮 | [Goal 服务](../deepseek-harness/packages/goal/goal/README.md)只拥有事件化状态和默认轮次上限；真正调度下一轮的是独立的 [goal-round-driver](../deepseek-harness/packages/goal/goal-round-driver/README.md)。开发时必须保持状态与调度分离。 |
| Skill 来源被描述成一个固定全局优先级列表 | 当前 [filesystem provider](../deepseek-harness/packages/skill/skill-filesystem/README.md)只定义它自己的 project/custom/user rank；运行时和随附 Skill 可能来自其他 Provider，最终合并规则应由 Skill Registry 说明。 |
| “当前工作区存在 euos-service-j 和 euos-vue” | 当前可见工作区只有 `deepseek-harness` 和空的 `开发文档`。没有这两个项目，不能据此决定 Java 接口或 Vue 现有组件的改造细节。 |
| Standard 固定拥有 25 个工具 | 这是当前随附 Web 组装的精确测试事实，不是 Runtime 永久不变量；Profile、Bundle、Preset、平台条件和用户覆盖都能改变目录。 |
| “完整、成熟”等定性词 | 源码仍是 developer preview，Session 格式无兼容承诺；应以可验收行为替代成熟度判断。 |

## 旧报告识别出的真实漂移

以下三点在当前 HEAD 仍能观察到，旧报告判断正确：Standard Preset 的 Spawn 和 Fork 都配置为 continuable；MCP 默认重连参数仍为 500ms 起步、30 秒上限、10 次；Cordis 的部分旧 Skill 仍出现 `cordis_mount`，而真实动态插件工具为 `cordis_define`、`cordis_run`、`cordis_stop`、`cordis_undefine`。这说明开发计划必须以实际组装、源码和测试共同定案。

## 当前版本新增或变化的能力

与旧审计提交相比，当前源码增加了 Python Code Runtime、文件引用 Context、Authorization 能力、持久 PowerShell PTY，以及私有实验性的 Agent Teams；Web Client 包结构也发生了重组。这些变化不改变本计划的核心路线，但说明不能按旧报告逐包复刻。

## 最终结论

旧报告的核心架构结论可以保留，尤其是“模型负责语义判断，本体负责确定性许可和状态约束”。需要丢弃的是旧版本精确数量、绝对路径、对组合结果的永久化描述，以及把 Goal 状态和续跑调度合并成一个模块的做法。本计划据此选择精简自研，而不是 Fork 当前 DSH。
