# 目标范围、复刻边界与版本路线

## 总目标

实现一个可学习、可解释、可测试的 Agent Runtime：底层行为完整复刻固定版本 Cordis/DeepSeek Harness 的关键核心，上层增加确定性的本体约束。模型负责语言理解和开放式推理；生命周期、权限、工具许可、事实状态和副作用归属由代码负责。

## 两张完成清单

项目同时维护两张清单，不能互相替代：

### A. 核心复刻清单

包括 Cordis 生命周期、DSH Scope、Session、LLM 抽象、Tools、Agent/Loop、System Prompt、安全、恢复与压缩。验收依据是固定版本的行为合同和测试。

### B. 本体扩展清单

包括本体模型、事实存储、动作映射、策略判定、计划、回写、补偿和解释性审计。验收依据是本项目的领域不变量，不声称与上游等价。

## 核心复刻范围

### 必须完整学习和实现

- 多形态 Effect、Fiber 状态机、失败回滚、并发/重入/停稳；
- 父子插件、Context、Service、依赖注入、隔离和完整事件语义；
- DSH Scope 标签、父链、作用域路由与分层存储；
- Session 仅追加日志、Surface、请求信封、Turn/Step 不变量；
- 归一化 LLM 流和恰好一个终止结果；
- 工具注册、可见性、schema 校验、策略、Guard、执行、定稿与通知；
- Agent 收件箱、步骤准入、Turn/Step 循环、事务式创建和销毁；
- 系统提示词、变量、动态上下文和工具目录稳定排序；
- 审批和沙箱的 fail-closed；
- 持久化、崩溃修复、投影、压缩锁和工具配对边界。

### 要学习，但可在产品里延后启用

- Loader 声明式组合和 HMR；
- PTC `run_code` 完整产品模式；
- 多模型提供方、附件富内容、Zstandard 优化；
- Todo、Plan、Goal、Jobs、Subagent、Workflow、Skills、MCP；
- API、SDK、ACP 和 Web 产品表面。

“延后启用”不等于从课程删除。必须知道它依赖哪些内核合同，差异账本中写清交付阶段。

### 不追求逐项复制

- 上游全部包、品牌文案和完整 Web UI；
- 原仓库构建生成器和双语文档流水线的逐文件复制；
- 所有模型提供商、平台后端和实验性 Agent Team；
- 相同类名、相同目录或相同行级实现。

## 本体 Runtime 的产品成功标准

- 自然语言目标进入 Agent Loop 后，模型只看到当前事实允许的候选动作；
- 工具执行前基于最新事实版本再次判定，防止 TOCTOU；
- 动作结果以幂等、可审计方式回写事实；
- 后置条件不成立时进入补偿或重规划，而不是伪造成功；
- 每次候选生成、拒绝、审批、执行和回写都有稳定决策记录；
- 进程崩溃后能区分“没有执行”“可能执行但结果未知”“已提交”；
- 用户可从 API/Web 查看模型轨迹、工具、权限、本体规则和事实版本。

## 仓库边界

本项目采用当前 monorepo，不修改被忽略的 `deepseek-harness/`。推荐边界：

```text
apps/
  runtime/                 CLI、Host、协议生命周期
  web/                     Web 控制台
packages/
  contracts/               品牌 ID、JSON、错误、协议
  kernel/                  Cordis 核心行为复刻
  scope/                   DSH Scope 行为复刻
  session/                 事件日志、Surface、持久化、投影
  llm/                     归一化模型协议与 DeepSeek adapter
  tools/                   注册表、schema、执行管线
  agent/                   Agent 句柄、收件箱、循环
  system-prompt/           提示词与工具目录组装
  security/                审批、策略和沙箱 seam
  ontology/                本体、事实、动作、规划与补偿
  extensions/              Todo/Plan/Goal/Jobs/Skills/MCP 等
  protocol/                API、SDK、ACP
```

拆包依据是独立合同、生命周期和依赖方向，不是为了模仿上游包数量。

## 版本路线

### L0：学习基线

完成 K00，固定上游提交、测试工具和差异账本。没有可运行产品功能，但后续结论可复现。

### L1：生命周期内核

完成 K01–K06。Effect/Fiber 在同步失败、异步失败、取消式卸载、并发、重入和父子级联下都能停稳。

### L2：组合内核

完成 K07–K13。Plugin/Context/Service/Event/Loader/Scope 形成可更新、可隔离、可逆的插件世界。

### R1：单 Agent 内存闭环

完成 04–09。Session、LLM、Tools、Agent Loop 和 Prompt 在内存中形成可测试闭环。

### R2：安全和恢复闭环

完成 10–12。权限、沙箱、持久化、崩溃修复和压缩达到 fail-closed 与可回放要求。

### O1：本体约束闭环

完成 13–15。候选、执行前 Guard、结果回写、补偿和重规划可演示。这是首个具有项目差异化的里程碑。

### X1：长期任务和生态能力

完成 16–23。加入可恢复协作状态、后台任务、子 Agent、Workflow、Skills 与 MCP。

### P1：产品接入

完成 24–28。API、SDK、ACP、Web、可观测性、安全与发布门禁完备。

## 每个里程碑的出口条件

- 该阶段所有 MUST 行为通过测试；
- 差异账本无未说明项；
- 前一阶段回归测试全部通过；
- 至少一个故障注入演示，而不只是快乐路径；
- 所有活动句柄在测试结束时完全停稳；
- 文档和代码在同一提交中保持对应，且提交不混入其他阶段。

## 外部系统假设

当前工作区没有可供审计的既有 Java 领域服务或 Vue 业务项目。课程只定义 `OntologyPort`、`BusinessToolPort` 和客户端协议。在真实接入前必须单独审计鉴权、事务、幂等键、错误码、数据版本和补偿能力，不在这里臆造接口。
