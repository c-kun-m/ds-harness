# 技术栈与工程约束

## 技术选型

| 层 | 选择 | 约束 |
|---|---|---|
| 运行时 | Node.js 24 LTS | 使用原生 `AbortController`、Web Streams、`AsyncLocalStorage`、Worker Threads 和 `node:sqlite`；锁定 24.x，不跟随 Current 版本。 |
| 语言 | TypeScript，`strict: true`，ESM | `module` 和 `moduleResolution` 使用 `NodeNext`，启用 `noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`、`verbatimModuleSyntax`。 |
| 包管理 | pnpm 11 workspace | 根目录只保留统一 lockfile；内部依赖使用 `workspace:*`。 |
| 外部输入校验 | Zod 4 | Zod Schema 是配置、RPC 和工具参数的运行时真源；只对可表示类型生成 JSON Schema。 |
| 模型适配 | 自定义 `LlmAdapter` + `@earendil-works/pi-ai` Provider | Agent 只依赖归一化流协议，不依赖供应商对象；第一条真实路由只实现 DeepSeek。 |
| 会话存储 | JSONL 事件日志 + `node:sqlite` 投影索引 | JSONL 是审计真源；SQLite 用于列表、查询和 Web 读模型，不反向修改事件日志。 |
| 压缩 | 先原始 JSONL，后启用 Node Zstandard | 在恢复语义稳定前不引入压缩；压缩只改变物理编码，不改变逻辑事件。 |
| 并发 | Promise、AbortSignal、Worker Threads | 工具并发由自研有界调度器控制；Workflow 脚本放 Worker，不在主线程 `eval`。 |
| 进程 | `node:child_process` + 独立 Subprocess Provider | 所有 Shell、MCP stdio 和外部 Agent 统一由该 Provider 管理进程树和取消。 |
| 协议 | JSON-RPC 2.0 + WebSocket；stdio 用于 SDK/ACP | 请求/响应和事件通知使用同一类型目录；HTTP 只提供健康检查和静态资源。 |
| Web | Vue 3、TypeScript、Vite、Pinia、Vue Router | UI 只消费投影和通知，不从原始事件自行推导业务真相。 |
| 测试 | Vitest、fast-check、Playwright | 单元测试状态机和不变量，属性测试事件重放，Playwright 验证用户可见流程。 |

Node 24、TypeScript ESM、Vue + TypeScript、Vite、Vitest、Playwright、Zod JSON Schema 和 JSON-RPC 的选择都对应当前官方文档；依赖安装时锁定精确版本，不在计划文档中写易过期的小版本号。

## 为什么不直接 Fork DSH

当前 DSH 是 developer preview，内部包数量和组合规则变化快。直接 Fork 会同时继承 Cordis、Typert、构建生成器、双语文档门禁和大量产品包的维护成本。新项目只复用其设计不变量：可逆插件、作用域工具、事件化会话、受控执行管线和模型可见即有日志。

## 为什么自研最小插件内核

手写实现的学习目标包括生命周期、作用域和 Waterfall 语义，因此不直接复制 Cordis。内核只实现当前路线必需的 Service 注册、子作用域、可逆 Effect、通知事件、串行事件和 Waterfall。禁止在 MVP 中加入热更新、依赖自动等待、配置 DSL 和浏览器插件树。

## TypeScript 工程约束

- 所有跨模块 ID 使用 brand 类型，禁止裸字符串混用。
- 跨进程、配置、模型输出、工具参数、数据库和事件文件必须运行时校验；同进程已验证对象不重复校验。
- 公共联合类型使用判别字段，封闭联合必须 `assertNever`。
- 所有异步公共操作接收或明确拥有 `AbortSignal`。
- 所有注册函数返回 disposer；卸载必须可重复调用。
- 所有事件载荷必须是 lossless JSON；`undefined`、函数、Symbol、BigInt 和循环引用不得进入日志。
- 配置错误在启动时失败，运行状态错误在最早可判断处失败，不做静默降级。

## 目录和依赖规则

依赖方向固定为 `contracts → kernel/session/llm → tools/agent → ontology/extensions → protocol/apps`。下层不得导入上层。Ontology 可以依赖工具和会话协议，但 Agent Loop 不得直接导入具体本体实现，只依赖 `OntologyPolicy` 接口。
