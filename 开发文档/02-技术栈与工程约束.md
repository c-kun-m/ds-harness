# 技术栈、行为约束与工程纪律

## 技术选择

| 层 | 选择 | 核心约束 |
|---|---|---|
| 运行时 | Node.js 24 LTS | 原生 AbortController、Web Streams、AsyncLocalStorage、Worker Threads；锁定 24.x |
| 语言 | TypeScript strict ESM | NodeNext、noUncheckedIndexedAccess、exactOptionalPropertyTypes、verbatimModuleSyntax |
| 包管理 | pnpm 11 workspace | 单 lockfile，内部依赖 `workspace:*` |
| 外部校验 | Zod 4 或 Standard Schema 兼容边界 | 配置、协议、日志和工具参数在信任边界校验；不得把 TS 类型当运行时证明 |
| 模型层 | 自有 `LlmAdapter`，首个 DeepSeek adapter | Loop 只依赖归一化流；adapter 拥有供应商协议和失败映射 |
| 存储 | Session 逻辑日志 + JSONL provider + SQLite 投影 | 日志是真源；投影可重建，不反写真源 |
| 并发 | Promise、AbortSignal、受控池、Worker | 明确启动/完成/提交顺序；不以无界 Promise.all 代替设计 |
| 协议 | JSON-RPC 2.0 + WebSocket，stdio 用于 SDK/ACP | 版本、背压、身份和错误码进入公共合同 |
| Web | Vue 3 + TypeScript + Vite + Pinia | UI 只读投影和通知，不在浏览器重写领域真相 |
| 测试 | Vitest + fast-check + Playwright | 单元/属性/故障/并发/集成/端到端分层 |

依赖安装锁定精确版本；课程只固定大方向，不在长期文档中复制容易过期的补丁号。

## 为什么重实现，而不是直接依赖 Cordis

本项目的学习目标包括生命周期、所有权、作用域、依赖变化、重入和停稳。如果直接把 Cordis 当黑盒依赖，这些最重要的能力不会被真正掌握。

因此采用“行为复刻、实现独立”的方式：

- 固定上游提交作为行为基线；
- 用公共合同和黑盒测试定义目标；
- 自己设计内部结构，不逐行翻译源码；
- 读上游用于复盘和发现遗漏；
- 所有差异进入 `PARITY.md`。

这不是“最小内核”。HMR、依赖自动等待、配置更新、异步 Effect 和重入卸载都属于完整课程，只是按 K00–K13 分阶段实现。

## TypeScript 约束

### 身份与联合类型

- 跨模块 ID 使用 brand，禁止把 SessionId、AgentId、ToolCallId 当普通 string 混用；
- 公共状态使用判别联合或 enum + 受控转移，禁止多个布尔值表达互斥状态；
- 封闭联合必须 `assertNever`；
- 精确对象边界拒绝未知字段，内部借用对象要明确冻结或复制策略。

### JSON 与信任边界

- 模型输入、工具参数、配置、RPC、持久记录和外部进程输出必须运行时校验；
- 日志只允许 lossless JSON：拒绝 undefined、函数、Symbol、BigInt、循环引用和非有限数字；
- 同进程已验证对象可以借用，但发布后不可被调用方静默修改；
- 原始错误对象不进入协议或日志，先映射到稳定 error record。

### 取消

- 每个可能等待外部工作或长期运行的公共操作接收/拥有 AbortSignal；
- 先检查调用前取消，再安装 listener，再检查交接竞态；
- listener 在结算时解除；
- abort 是请求，不是停稳证明；
- 更具体的已知失败不得被晚到的取消覆盖。

## 生命周期约束

### 注册皆可逆

服务、事件、工具、提示词、provider、timer 和子任务注册都必须返回精确 disposer。旧 disposer 只能删除它创建的记录，不能按名称删除后继实例。

### 先拥有，再发布

任何新资源按以下顺序创建：

1. 在私有状态中构造；
2. 先把回滚/清理能力交给结构拥有者；
3. 完成校验和 setup；
4. 原子发布；
5. 发布通知失败时由已有所有权回滚。

禁止先广播“已创建”，再补登记 disposer。

### 完全停稳

`dispose()` 的 Promise 只有在不再接受工作、已接收工作结算、子资源释放、所有清理被观察后才能兑现。重复 dispose 返回同一个停稳事务或等价结果，不得重复副作用。

### 创建期间卸载

Effect/插件 setup 内可能同步触发自身或父级卸载。实现必须在运行用户 setup 之前建立 owner wrapper 和状态屏障，使重入清理能找到正在创建的资源。

## 并发约束

- 每个模块写出最大并发数和公平性；
- 并行执行不自动允许乱序提交；
- 不同 sibling Effect 可以并发清理，但每个 Effect 内部 disposer 保持逆序串行；
- 工具执行可以并发，策略和持久结果按模型序提交；
- 用 deferred/barrier 写确定性交错测试，不依赖 sleep；
- 所有共享可变状态必须说明串行化点：队列、锁、generation、revision 或单线程 actor。

## 错误约束

- 配置和结构错误尽早失败，最好在副作用前；
- 运行错误带稳定 code、阶段、身份和 cause；
- 业务失败、协议失败、取消、超时和基础设施失败不能都叫 `UNKNOWN_ERROR`；
- 主操作失败后清理也失败时，保留主因并聚合/记录清理错误；
- 纯通知监听器失败通常隔离，门禁/waterfall 失败通常传播；每个事件必须明确属于哪一种；
- 不允许未处理 Promise rejection。

## Session 与恢复约束

- 日志 seq 连续、仅追加；
- 内存 append、durable append 和 flush barrier 是不同概念；
- 每个已开始 Turn/Step/Tool/Approval/Compaction 都有配对或可恢复的终态；
- 崩溃修复追加证据，不重写已提交事实；
- Surface 替换不删除原始日志；
- projection 是纯折叠，可从同一事件序列确定重建。

## 安全约束

- 没有审批 responder、审批异常或取消时拒绝；
- 沙箱后端不可用时拒绝，不降级为 unrestricted；
- 权限提升只允许严格更宽的封闭阶梯，且只对单次调用有效；
- Prompt 是引导，不是权限边界；
- 本体候选筛选不能代替执行前 Guard；
- 进程内身份用于归因，不是跨进程授权证明。

## 目录依赖方向

```text
contracts
  ↓
kernel + scope + session + llm
  ↓
tools + system-prompt + agent
  ↓
security + extensions + ontology
  ↓
protocol + apps
```

下层不能导入上层产品包。Agent Loop 只依赖 `OntologyPolicy` 接口，不导入具体领域模型；MCP、Skills、Workflow 等扩展通过 Tools/Session/Scope 接入，不修改 Loop 核心。

## Git 与改动纪律

- 每完成一个课程或一组原子文档改动立即 commit；
- 不使用 `git commit --no-verify`；
- 不把被忽略的 `deepseek-harness/` 纳入外层仓库；
- 不覆盖用户未完成的工作；
- 每次提交只包含本课相关文件，便于回退和比较。

## 质量门禁

每个 package 至少具备 `typecheck`、`test` 和 `build`。核心生命周期包还必须具备：

- 并发/重入测试；
- 未处理拒绝探测；
- fake timer 或受控 scheduler 测试；
- disposer/Abort listener 泄漏检查；
- 固定上游代表性 parity 测试；
- `PARITY.md` 差异账本。
