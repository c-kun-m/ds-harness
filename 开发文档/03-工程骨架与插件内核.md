# 工程骨架与插件内核：K00–K13 完整路线

## 本阶段目标

从零实现一个行为完整、可测试的同进程插件内核，并理解它如何支撑 DeepSeek Harness。完成后，你应能处理：

- 同步、异步、Iterable 和 AsyncIterable Effect；
- 插件加载、失败、卸载、更新、重启和 HMR；
- 并发清理、重复释放和 setup 内重入卸载；
- 父子 Fiber 所有权和原子发布；
- Context、Service、依赖注入、隔离与访问追踪；
- 完整事件语义；
- DSH Scope 的作用域标签、父链、事件路由和分层注册。

当前简单 `EffectStack` 是 K01 的热身，不是本阶段的最终架构。

## 为什么要拆成 14 课

Effect、Fiber、Context、Service、Registry 和 Events 相互依赖。一次性照着上游写，会得到能编译但无法解释的代码。课程先建立最小概念，再逐步加入失败和并发，最后组合；每一课都保留可运行验收点。

## 阶段演示

### 演示 A：Effect 失败回滚

一个 Effect 先注册两个清理，再同步抛错。外部看到原错误；两个清理逆序执行；清理自身失败被记录/聚合；Effect 不再留在 owner 中；重复释放不再执行。

### 演示 B：重入卸载

插件 setup 中同步触发自己的父插件卸载。系统不丢失 owner wrapper、不发布半成品插件、不产生未处理拒绝，父子 Fiber 最终都进入 DISPOSED。

### 演示 C：依赖消失与恢复

消费者声明 required 服务。Provider 激活后消费者加载；Provider 卸载时消费者先卸载并仍能在清理期访问服务；Provider 恢复后消费者重新加载。optional 依赖变化只通知，不强制卸载。

### 演示 D：HMR 原子替换

旧插件正在提供服务，新模块加载和校验成功后才切换；新模块 setup 失败时旧实例继续可用；切换成功后旧 disposer 不能删除新服务。

### 演示 E：Scope 路由

root、parent、child 三个 Scope 注册同名层数据和 scoped listener。child 查询按全局→远祖→近祖→自身合并；child 事件可到 ancestor，ancestor 事件不能下泄；释放 child 只撤销 child 所有内容。

## 本阶段统一不变量

1. 注册就是 Effect，且 disposer 精确、幂等；
2. 用户 setup 运行前结构 owner 已有回滚能力；
3. 状态为 UNLOADING/DISPOSED 时不能接纳新 Effect；
4. 单 Effect 内逆序串行清理，Fiber sibling Effect 可并发等待；
5. dispose Promise 表示完全停稳；
6. 父插件发布子 Fiber 前先拥有子 disposer；
7. required 服务消失时消费者不能继续 ACTIVE；
8. Service 解析同时遵守作用域、隔离和 provider 状态；
9. 事件 listener disposer 只移除精确 listener；
10. 更新/HMR 失败不能留下半个新世代；
11. Scope 可见性和资源生命周期来自同一个 Context；
12. 任何观察者失败都按事件合同传播或隔离，不能随机吞错。

## 不允许的捷径

- 用一个数组同时承担所有 Fiber、Effect、Listener 和 Child ownership；
- 用对象属性是否存在代替明确状态机；
- dispose 只设置布尔值，不等待异步清理；
- required 服务未就绪时返回 undefined 让业务层自己猜；
- HMR 先卸载旧插件，再尝试加载新插件且失败后无法恢复；
- 事件过滤用可变全局“当前 scope”；
- 通过遍历同名 key 删除注册，不检查身份；
- 测试靠 `setTimeout` 猜并发顺序。
