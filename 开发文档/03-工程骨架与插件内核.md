# 工程骨架与插件内核

## 目标

建立最小可逆运行内核，使模型、工具、会话、策略和产品接口都以插件注册，不需要修改 Agent Loop 本体。该模块只解决同进程组合和生命周期，不负责远程插件、热更新或安全隔离。

## 前置条件

完成 [技术栈与工程约束](02-技术栈与工程约束.md)。

## 核心接口

- `Context`：读取服务、创建子作用域、注册 Effect、派发事件。
- `ServiceMap`：通过 TypeScript declaration merging 扩展服务键和类型。
- `Plugin<Config>`：`apply(ctx, config)` 返回 `void` 或 disposer。
- `Scope`：拥有自己的注册层，并沿父链读取服务和工具。
- `Effect`：创建时登记，卸载时逆序执行；重复 dispose 不重复副作用。
- `EventMap`：支持 `notify`、`serial` 和 `waterfall` 三种模式。
- `Fiber`：一个插件实例的生命周期容器，统一等待异步清理。

## 手写顺序

1. 建立 pnpm workspace、基础 tsconfig、lint、test、build 脚本。
2. 实现 `DisposableStack` 风格的 Effect 容器，先写逆序释放和错误聚合测试。
3. 实现服务注册表；同一作用域重复服务名必须失败，子作用域允许显式 shadow。
4. 实现 `Context.child()`，子作用域释放时只撤销自己的注册和监听器。
5. 实现通知事件和串行事件。
6. 实现 Waterfall；每个监听器必须调用 `next()` 才继续，未调用表示短路。
7. 使用 `AsyncLocalStorage` 保存当前 Agent/Session initiator，禁止把调用者身份放进全局变量。
8. 实现插件加载事务：`apply` 失败时回滚该插件已经登记的全部 Effect。

## 关键不变量

- 注册就是 Effect，卸载后不能残留服务、工具或监听器。
- 子作用域能读取父层，但父层不能读取子层。
- disposer 只能删除自己注册的精确对象，不能误删同名后继对象。
- Waterfall 短路和异常传播必须可预测；监听器异常不被吞掉。
- Provider 卸载必须先停止接受新工作，再等待已接受工作到达静止点。

## 测试

- 插件成功加载、失败回滚、重复卸载。
- 父子作用域 shadow、隔离和级联释放。
- 同名服务竞争和旧 disposer 误删保护。
- Waterfall 的继续、改写、短路、异常和异步顺序。
- 异步任务中 initiator 身份不串线。

## 完成标准

用三个测试插件证明：根插件提供日志服务；Agent 子作用域覆盖 Persona；工具插件注册后可见，卸载后立即不可见；任一插件加载失败不会污染 Context。
