# K00：工程、测试与源码阅读基线

## 这一课解决什么

后续课程大量涉及 Promise 交错、重入和上游行为对照。如果测试环境不能确定地控制异步，失败会被误判为“偶发”；如果上游版本不固定，今天通过的等价测试明天可能无意义。

本课不实现业务功能，只建立可复现的学习实验室。

## 学习目标

- 固定 Node、pnpm、TypeScript 和上游提交；
- 能区分外层项目和被忽略的上游参考仓库；
- 建立单测、类型检查、构建和未处理拒绝门禁；
- 建立 deferred、barrier 和事件记录器等异步测试工具；
- 建立 `PARITY.md`，能从上游测试提取黑盒行为而不照抄实现。

## 功能合同

### 基线

- MUST：`git -C deepseek-harness rev-parse HEAD` 等于课程固定提交；
- MUST：外层 Git 忽略整个 `deepseek-harness/`；
- MUST：根仓库的 build/test/typecheck 不扫描或打包上游目录；
- MUST：项目能在全新安装后用单一命令运行相关测试；
- MUST NOT：通过修改上游源码改变参考行为。

### 异步测试工具

你需要能表达：

- “操作已经启动，但尚未允许完成”；
- “等待 A 到达屏障后再启动 B”；
- “记录同步调用顺序与 Promise 结算顺序”；
- “确认一个 Promise 在某个 checkpoint 前仍未结算”；
- “测试结束时确认没有未处理 rejection”。

这些工具只服务测试，不进入生产包公共 API。

### 差异账本

每个条目必须包含上游行为、当前状态、自动证据和决定。没有测试证据的“应该一样”不能标为通过。

## 你先做的设计题

1. 为什么 `await Promise.resolve()` 比 `setTimeout(10)` 更适合检查微任务边界，但仍不能证明所有异步任务停稳？
2. deferred promise 如果测试失败前没有 reject/resolve，会怎样让测试进程挂住？如何兜底？
3. 上游测试依赖私有字段时，如何改写成本项目的黑盒测试？
4. 怎样防止 parity 测试过度锁定错误文本、日志格式或内部执行顺序？

## 实现任务

1. 检查并固定 workspace 的 engines、packageManager 和 TypeScript 配置；
2. 为 kernel package 建立 `test`、`typecheck`、`build`；
3. 建立测试专用 deferred/barrier/call-log；
4. 增加一个故意异步拒绝的测试，证明门禁能观察它；
5. 新建 `packages/kernel/PARITY.md`，填入 K01 将使用的首批条目；
6. 写一条脚本或文档命令验证上游 HEAD，不自动修改它。

## 测试矩阵

| 场景 | 预期 |
|---|---|
| 正常 typecheck/test/build | 全部退出 0 |
| 上游 HEAD 正确 | 基线检查通过 |
| 上游 HEAD 不正确 | 给出期望/实际提交，失败且不自动 checkout |
| deferred 正常释放 | 等待者只在 resolve 后继续 |
| deferred 拒绝 | cause 可被测试观察 |
| barrier 多参与者 | 未达到数量前无一继续，达到后全部继续 |
| 未处理拒绝 | 测试失败，不只打印 warning |
| 测试失败后的清理 | fake timer、listener、deferred 不污染下一测试 |

## 源码复盘

这一课不必深读 Cordis 实现。只确认：

- [`deepseek-harness/package.json`](../../deepseek-harness/package.json) 的脚本和 engine；
- [`deepseek-harness/pnpm-workspace.yaml`](../../deepseek-harness/pnpm-workspace.yaml) 的包范围；
- [`deepseek-harness/vendor/README.md`](../../deepseek-harness/vendor/README.md) 的 Cordis 固定版本和本地加固说明；
- 上游测试如何使用 deferred 控制重入和异步清理。

## 完成标准

- 单命令可以运行 kernel 测试；
- 测试不靠任意 sleep；
- 上游目录不会出现在外层 `git status`；
- 差异账本已建立；
- 你能演示一个未处理拒绝会使测试失败。

3. “测试结束”与“系统完全停稳”为什么不是同一件事？
