# K10：完整事件系统与分发语义

## 这一课解决什么

“事件”不是一个统一的 `emit()`。通知、并行观察、串行门禁、首个结果和 around middleware 对错误、短路、返回值和顺序的要求完全不同。若混用，安全门禁可能被 observer 吞错，纯通知也可能因一个插件失败阻塞整个运行时。

## 事件模式

| 模式 | 调度 | 返回 | 典型用途 |
|---|---|---|---|
| emit | 同步逐个调用，不等待 Promise | void | 轻量同步通知 |
| parallel | 同时等待全部 | settled/聚合错误 | 独立异步观察者 |
| serial | 依次等待，遇 bail 停 | 首个 bail 值 | 依次询问/决策 |
| bail | 同步依次，遇 bail 停 | 首个 bail 值 | 同步查询 |
| waterfall | around middleware `next()` | 最终折叠值 | 执行包装、可重写流水线 |

固定基线的 bail 值是除 `null`、`false`、`undefined` 外的任何值；`0` 和空字符串也会 bail。你的合同必须明确这一点。

## Listener 维度

- filter：按 dispatch 的 Context/target 过滤；
- global：绕过普通 filter；
- prepend：在同组前插；
- once：调用前先 dispose，防止重入第二次触发；
- thisArg：决定调用 receiver/过滤上下文；
- 精确 disposer：只移除这一条 listener record。

## 功能合同

- MUST：每个模式有独立、可文档化的错误和短路语义；
- MUST：listener 顺序稳定，prepend 行为确定；
- MUST：once 在调用用户 callback 前先撤销；
- MUST：disposer 精确且幂等；
- MUST：parallel 等待所有 listener，并报告全部拒绝；
- MUST：serial 串行，遇 bail 不再调用后续；
- MUST：waterfall 的 `next()` 只能按合同调用，重复/越界行为明确；
- MUST：filter 基于 dispatch Context，不读可变全局；
- MUST：global listener 的绕过边界明确；
- MUST：listener 注册归属 Effect，owner dispose 自动撤销。

## 测试矩阵

| 场景 | 预期 |
|---|---|
| 普通顺序 + prepend | 稳定顺序 |
| once 内重入 | 只调用一次 |
| 旧 disposer/同 callback 新注册 | 旧句柄只删旧记录 |
| parallel 一同步抛、一异步拒绝 | 其余都运行，错误聚合 |
| serial 返回 false/null/undefined | 继续 |
| serial 返回 0/空串/对象 | bail |
| bail 同步 | 首个 bail 后停止 |
| waterfall before/after | 洋葱顺序正确 |
| middleware 不调用 next | 合法短路并返回其值 |
| middleware 调两次 next | 稳定拒绝 |
| scoped filter/global | 可见性符合 Context |
| owner dispose | listener 立即不可见且等待停稳 |
| listener 注册/dispatch 并发 | generation 策略明确 |
