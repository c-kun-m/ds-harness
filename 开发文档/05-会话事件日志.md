# 05：Session 仅追加事件日志、Surface 与请求信封

## 本课定位

Session 是 Agent Runtime 的审计和恢复真源，不是聊天消息数组。模型消息、UI 时间线、Todo/Goal 状态都应从事件折叠得到。本课只做内存逻辑日志；11 再实现 durable provider。

## 学习目标

- 建立连续 seq、不可变 append 和声明合并事件表；
- 区分原始日志、模型 Surface、实时 chunk 和领域投影；
- 固定 Turn/Step/Tool 的配对不变量；
- 记录足以重建模型调用的 request header/envelope；
- 支持 seed/fork 的稳定完成 Turn 前缀；
- 为未知事件和格式版本制定 fail-closed 规则。

## Session Header

至少包含 formatVersion、id、创建时间、cwd、可选 parent/fork lineage、isSeeded、精确 inheritedEventCount、委派深度和创建来源。`isSeeded` 与 inherited cut 分开：空 seed 也必须与全新会话区分。

## 事件信封

每个事件至少有：

- `type`：封闭/可扩展事件名；
- `seq`：从 0 连续；
- `time`：记录时间，不作为顺序真源；
- `data`：lossless JSON；
- 可选 `ignorable`：当前版本不认识时是否允许跳过；
- 可选 surfaceOp/sourceEventSeqs：只允许指定 surface 事件使用。

append 必须在接纳时复制/冻结。调用方保留的对象之后变化，历史不能变化。

## 核心事件与配对

```text
turn/start
  step/start
    user/message 或运行时上下文
    request/header        # 完整规范请求信封/路由
    assistant/chunk *
    assistant/message
    tool/call *
    tool/result *
  step/end
turn/end
```

真实事件字段以你定义的 map 为准，但必须证明：

- Turn 不嵌套；
- Step 只能属于当前开放 Turn；
- tool result 引用当前/允许范围内已存在且未结算的 call；
- 每个 call 最多一个结果；
- end 原因属于封闭词汇；
- 崩溃修复可以追加 closer，而不是修改旧事件。

## Surface

只有 `user/message`、`assistant/message`、`tool/result`（或你明确的等价集合）进入模型 Surface。`assistant/chunk` 只用于实时 UI/诊断，不重复变成模型消息。

Surface 操作：

- append：增加一个可见节点；
- replace：用一个新节点遮蔽一段已存在 Surface 范围；
- 原始事件永不删除；
- sourceEventSeqs 让派生节点可追溯原始证据。

12 的 compaction 标记事件只写日志，不能自己进入 Surface。

## 请求信封

每个真正模型调用前记录 canonical request header，足以重建当时的：provider/model、推理设置、max tokens、系统提示词/工具/历史的稳定引用或规范值、session prefix 边界、调用序列。日志写入失败时不得调用模型。

## Fork/Seed

- 只能继承从 seq 0 开始的连续前缀；
- cut 必须落在稳定完成 Turn 边界；
- 不继承开放 Turn；
- inheritedEventCount 是显式 header 数据，不能通过当前总长度猜；
- child 后续 seq/offset 语义要明确，不能混淆物理继承与自有事件。

## 实现任务

1. 定义 SessionEventMap 与联合生成；
2. 实现 append/snapshot/listener；
3. 实现增量 invariant tracker；
4. 实现 Surface fold 和 deriveMessages；
5. 实现 request header 构造/验证；
6. 实现从事件数组 prepare/rebuild；
7. 实现 seed/fork cut 校验；
8. 定义未知 event/format 的兼容策略。

## 测试矩阵

| 场景 | 必须观察到 |
|---|---|
| 多 Step 正常日志 | deriveMessages 确定且配对完整 |
| append 后修改输入 | 历史不变 |
| chunk + final message | chunk 不重复进入 Surface |
| 两个 tool calls | 结果与 call 身份/顺序正确 |
| 重复/悬空 result | invariant 拒绝 |
| seq 缺口/重复 | corruption/prepare 失败 |
| replace | Surface 变化，原日志不减少 |
| 未知 ignorable/non-ignorable | 前者按合同跳过，后者失败 |
| formatVersion 更高 | 明确 upgrade-required，不误读 |
| fork 稳定边界 | 完成 Turn 成功，开放 Turn 拒绝 |
| JSON 往返 | 日志与派生消息完全相同 |
| listener 抛错 | append 的权威提交策略明确 |

## 完成标准

- 任意合法日志 JSON 往返后投影相同；
- 所有非法配对有稳定错误；
- 请求 header 可由测试重建同一规范请求；
- Surface replace 不删除证据；
- fork 只接受稳定完成前缀。
