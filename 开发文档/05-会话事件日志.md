# 会话事件日志

## 目标

实现内存中的 append-only Session，使模型输入、模型输出、工具调用、工具结果和 Turn/Step 边界都能由事件重建。此阶段不写磁盘，先把逻辑协议和不变量做对。

## 前置条件

完成 [核心类型与错误模型](04-核心类型与错误模型.md)。

## 事件信封

`SessionEvent` 至少包含 `type`、连续递增的 `seq`、`time`、`data`、可选 `ignorable`、可选 `surfaceOp` 和 `sourceEventSeqs`。`SessionHeader` 包含格式版本、Session ID、创建时间、工作目录、父会话、seed 长度、委派深度和 Preset ID。

## 第一批事件

- `turn/start`、`turn/end`
- `step/start`、`step/end`
- `user/message`
- `request/header`、`request/context`
- `assistant/chunk`、`assistant/message`
- `tool/call`、`tool/result`
- `session/error`、`session/checkpoint`

## Surface 规则

模型历史不直接遍历全部事件，而是由 `surfaceOp` 投影。MVP 支持 `append` 和 `replace-range`：普通消息追加；压缩模块以后用摘要替换一个逻辑范围，但原事件仍保留。`assistant/chunk` 用于实时 UI 和重放，不重复进入模型历史；只有最终 `assistant/message` 进入消息投影。

## 手写顺序

1. 定义 `SessionEventMap` 和从 map 生成联合类型的泛型。
2. 实现 `Session.append()`：验证 JSON、复制输入、冻结、分配 seq、同步通知监听器。
3. 实现 Turn/Step 结构校验器，拒绝嵌套 Turn、跨 Step 工具结果和不连续 seq。
4. 实现 `deriveMessages(boundary?)` 和 surface fold。
5. 实现从事件数组重建 Session；未知必需事件失败，未知且 `ignorable: true` 的事件跳过。
6. 实现 fork seed 校验：必须从 seq 0 连续，并停在完整 Turn 边界。

## 关键不变量

- 模型可见即有日志；禁止仅在内存变量中拼接模型上下文。
- `tool/result` 必须引用对应的 `tool/call` 事件，并保持模型原始调用顺序。
- 事件对象追加后不可变，调用者不能通过保留引用修改历史。
- 任何失败 Turn 也必须有 `turn/end`，其中记录 completed、blocked、aborted、max-tokens 或 error。
- 格式版本变化与普通事件类型扩展分开处理。

## 测试

- 多 Step 正常日志重放后得到相同模型消息。
- chunk 不重复进入历史，最终 message 保留 source seq。
- 非法 seq、悬空工具结果、Step 越界和未知必需事件被拒绝。
- replace-range 后模型表面改变，但原始事件数量不减少。
- fork 只能截取闭合 Turn。

## 完成标准

给定一组手写事件，`deriveMessages()` 能产生确定的模型请求历史；把事件序列 JSON 序列化再加载后结果完全相同。
