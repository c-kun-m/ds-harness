# 模型适配与流式输出

## 目标

定义与供应商无关的模型接口，并完成第一条 DeepSeek 流式路由。Agent Loop 只能看到统一的请求、Chunk、使用量和失败类型，不能读取供应商 SDK 的原始对象。

## 前置条件

完成 [会话事件日志](05-会话事件日志.md)。

## 核心接口

- `LlmRegistry.register(provider, adapter)`：注册 Provider，返回 disposer。
- `LlmAdapter.resolve(request)`：把缺省配置解析成不可变 `ResolvedLlmRequest`。
- `LlmAdapter.stream(request, signal)`：返回 `AsyncIterable<StreamChunk>`。
- `PreparedLlmCall`：把一次请求绑定到解析时的精确 Provider，防止流式期间注册表变化。
- `ModelCatalog`：模型 ID、上下文窗口、输入模态、最大输出、工具调用和结构化输出能力。

## 统一 Chunk

MVP 支持 `text-delta`、`reasoning-delta`、`tool-call-start`、`tool-call-delta`、`tool-call-end`、`usage`、`finish` 和 `error`。`BlockAssembler` 必须把任意合法分片顺序组装为最终 `AssistantMessage`，并拒绝重复 Call ID、未闭合工具调用和 finish 后继续输出。

## 手写顺序

1. 定义模型请求、模型能力和流式 Chunk 联合类型。
2. 实现 Registry、路由解析和 Provider 生命周期。
3. 实现 `BlockAssembler`，先用脚本化 Chunk 写完所有状态测试。
4. 用 `@earendil-works/pi-ai` 包装 DeepSeek Provider，只在适配器内部做供应商字段映射。
5. 在请求发出前记录 `request/header` 和 `request/context`；日志写入失败时不得调用模型。
6. 记录每个原始 Chunk，再记录唯一的最终 `assistant/message`。
7. 实现有界重试：只有适配器标为 retryable 且尚未产生不可安全重放的结果时重试；重试复用同一份冻结请求。

## 配置

Provider、Model、Base URL、API Key 引用、最大输出 Token、思考模式和重试策略均为配置，不在代码中写死当前模型名。凭据只在调用边界解析，绝不写入 Session 或错误详情。

## 关键不变量

- 一个成功或达到 token 上限的 Provider 调用恰好产生一个最终 Assistant Message。
- 取消期间已经生成的非空文本可以记录为 `interrupted: true`，但不能伪装成完整答复。
- 请求头必须记录最终 provider/model/maxTokens 等影响重放的字段。
- 模型能力由精确 provider/model 路由给出，不用猜测默认值。
- 模型错误、协议错误和用户取消必须保持不同错误码。

## 测试

- 文本、reasoning、多工具调用交错分片的组装测试。
- 空输出、max-tokens、Provider error、传输断开、取消和重试测试。
- API Key 不出现在事件、日志和异常字符串中的安全测试。
- 使用脚本化 Adapter 跑一个无工具的单 Step 会话。
- 真实 API 测试单独标记，没有 Key 时跳过，不代替脚本化测试。

## 完成标准

Runtime 能用脚本化 Adapter 和真实 DeepSeek Adapter 分别输出流式文本，最终消息和使用量可从 Session 重放，取消不会留下一个看似成功的 Turn。
