# 工具注册与执行管线

## 目标

实现统一 Tool Runtime。模型只能看到当前 Agent 作用域允许的工具 Schema；模型提出调用后，所有执行必须经过同一条校验、审批、策略、超时、后处理和审计管线。

## 前置条件

完成 [模型适配与流式输出](06-模型适配与流式输出.md)。

## ToolDefinition

每个工具包含 `name`、`description`、Zod 输入 Schema、生成后的 JSON Schema、`execute`、`isConcurrencySafe`、可选 `timeoutMs`、可选 `finalizeContent` 和纯展示函数。工具返回 `ToolExecutionResult`，其中有 `content`、`value?`、`isError`、`error?`、`meta?`、`additionalContexts?` 和 `concludesTurn?`。

## 作用域和可见性

`ToolRegistry` 分为全局层和 Agent 子作用域层。同名注册只允许显式 shadow。`restrict({ allow?, deny? })` 同时影响模型 Schema 和执行查找：被隐藏的工具即使由恶意或陈旧模型直接点名，也必须拒绝执行。

## 固定执行顺序

```text
解析 arguments
→ Zod 校验
→ tools/pre-execute waterfall
→ ask 审批
→ 单调 Guard
→ tools/execute around waterfall
→ Tool body
→ tools/post-execute waterfall
→ finalizeContent
→ 冻结结果并发出 tools/result
→ Session 写入 tool/result
```

Guard 只允许返回拒绝理由或 abstain，不能强制放行。这样一个宽松插件不能覆盖另一个安全插件的拒绝。

## 手写顺序

1. 实现工具定义、注册、作用域查找和 Schema 输出。
2. 实现参数解析和验证错误到失败工具结果的映射。
3. 实现 pre/execute/post 三类 Waterfall。
4. 实现审批决议 `allow`、`deny`、`ask`；没有审批服务时 `ask` 必须拒绝。
5. 实现同步单调 Guard，并保护 Call ID、Tool Name 和 Agent 身份不被插件改写。
6. 实现 Deadline 驱动的 around timeout。
7. 实现结果 JSON 化、冻结、finalizer 和结果通知。
8. 实现 `parallel` 与 `exclusive` 分类；未知、隐藏、分类异常的工具一律按 exclusive。

## 并发调度

同一模型消息中的连续 parallel 调用进入有界滚动池；exclusive 调用形成前后屏障。pre-execute 和结果提交保持模型顺序，只有实际 dispatch/body 可以重叠。后一个调用在启动前重新分类，使运行时策略变化能够把它转为屏障。

## 关键不变量

- 每个已记录的 `tool/call` 最终有一个 `tool/result`，除非发生明确记录的 Runtime 崩溃。
- 工具 body 不能绕过 Guard、审批和超时。
- Code Mode、MCP 和 Workflow 内部工具调用以后也必须调用本 Runtime，不能直接调用函数。
- 展示函数是纯函数，不读取服务或修改状态。
- 工具结果按模型调用顺序提交，确保重放确定性。

## 测试与完成标准

覆盖未知工具、非法 JSON、Schema 错误、审批缺失、Guard 拒绝、超时、post 替换、finalizer、并发上限、exclusive 屏障、取消和结果有序性。完成后用 `echo`、`sleep`、`fail` 三个假工具证明完整管线。
