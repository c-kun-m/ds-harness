# 权限、审批与沙箱

## 目标

在工具执行前建立确定性的权限、人工审批和本地进程限制。该模块控制是否允许执行和文件副作用范围，不宣称提供完整多租户隔离。

## 前置条件

完成 [提示词、上下文与 Preset](09-提示词上下文与Preset.md)。

## 权限模型

第一版提供三个 Preset：`read-only`、`workspace-write`、`danger-full-access`。每个 Preset 展开为独立的 `SandboxPolicy`、`ApprovalPolicy` 和工具限制，不能让一个字符串在不同模块里被各自解释。

## 审批服务

`ApprovalService.request()` 输入 Request ID、Agent、Tool Call ID、工具名、参数摘要、风险说明和 AbortSignal，输出 `allowed-once`、`rejected`、`cancelled` 或 `unavailable`。没有审批通道时 `ask` 结果必须是拒绝。审批决定写入 Session，但不得记录 Secret 参数原文。

## Sandbox Provider

定义 `confine(argv, policy)`，返回真正要执行的 argv 和 enforcement 信息。MVP 可以先实现平台探测与 fail-closed 接口，再按平台接入 Bubblewrap/Landlock、Seatbelt 或 Windows Restricted Token + ACL。任何不可用后端都不能静默退回无沙箱执行。

## 手写顺序

1. 实现 Permission Preset 展开和启动期校验。
2. 实现 Approval Registry、一次性 Request 和超时/取消。
3. 在 Tool pre-execute 中加入风险分类和审批决策。
4. 把本体 Policy Guard 注册到单调 Guard 阶段，审批不能越过本体拒绝。
5. 实现 Subprocess Provider 和 Sandbox Provider 接口。
6. 先完成 `danger-full-access` 明示路径和不可用时拒绝，再开发实际平台 Runner。
7. 为文件工具增加 read-before-edit、路径 canonicalization 和写入意图事件。

## 安全边界

- `workspace-write` 主要限制文件写入，不限制网络、进程可见性、设备和同用户凭据读取。
- `danger-full-access` 不是“无风险”，只是操作员明确关闭本地文件限制和默认审批。
- 动态 Skill、Preset、Shell 和未来 Workflow 脚本都按受信任代码处理。
- 多租户生产部署必须使用独立容器、microVM 或远程执行 Provider，并同时替换文件和进程能力。

## 测试与完成标准

覆盖审批允许、拒绝、关闭、超时、通道缺失；覆盖路径穿越、符号链接、工作区外写入和 Sandbox 不可用。完成标准是一个写文件工具在 read-only 下拒绝，在 workspace-write 的工作区内经审批成功，在工作区外始终拒绝。
