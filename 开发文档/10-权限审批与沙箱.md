# 10：审批、权限预设、沙箱与 fail-closed

## 本课定位

安全能力分三层：工具策略决定“是否允许/询问”，Approval seam 获取一次决定，Sandbox 限制本地文件副作用。Prompt/Plan 不是安全边界；沙箱也不是完整多租户隔离。

## 学习目标

- 建立一次性、可取消、可审计的审批 seam；
- 没有 responder 或 responder 异常时 fail-closed；
- 将审批策略与沙箱模式保持为独立权威值；
- 用 Permission Preset 只做两个旋钮的用户友好捆绑；
- 建立 read-only/workspace-write/danger-full-access 的文件策略；
- 实现严格加宽的一次升权；
- 沙箱后端不可用时拒绝无约束运行。

## Approval 合同

### 请求与结果

结果封闭为：`allowed-once`、`rejected`、`cancelled`、`unavailable`。请求至少携带 request id、精确 Agent、tool name、可选 call id、原因和 AbortSignal。固定上游 seam 不把完整工具参数交给 responder；若本项目要展示参数摘要，必须先做工具拥有的安全 redaction，并记录差异。

### Policy

- `ask`：交给 scoped `approval/request` waterfall；没有最终 responder 返回 unavailable；
- `never`：在任何 responder 之前确定性拒绝，后续 prepend listener 也不能绕过；
- 当前只一次授权，不实现 allow-always/持久授权存储。

### 时序与审计

请求只允许在开放且未结束的 Turn 内：

```text
append approval/asked
→ responder waterfall 与 abort 竞速
→ 规范化结果（异常/非法值 → unavailable）
→ append approval/decided
→ 返回决定
```

任一审计 append 失败，不能返回一项未记录的允许。取消撤回问题，迟到回答丢弃。asked/decided 使用同 id 且在同一 Turn 内配对。

## Permission Preset

预设只把 sandbox mode + approval policy 捆绑：

- 可选预设由配置定义；
- 不匹配任何预设的实际组合推导为 `custom`，只能显示不能选择；
- apply 只修改实际变化的旋钮；
- 选择事件先于旋钮事件，保留用户意图；
- 设置默认只影响未来新会话；resume/seed 保留历史有效值并只补缺失事实。

## Sandbox 合同

### 模式

- read-only：不允许文件写入；
- workspace-write：写入限于规范化 workspace roots + 明确临时根；
- danger-full-access：关闭此文件限制，但不意味着无风险。

策略逐调用传入 provider，不固定在 provider 实例上。`confine(argv, policy)` 要么返回真实受约束 argv/enforcement 证据，要么抛出 `SANDBOX_UNAVAILABLE`；禁止静默 fallback unrestricted。

### Root 与路径

规范化绝对路径、解析符号链接、去重；不同平台 runner 和进程内文件栅栏必须使用同一 writable root 推导。只检查字符串前缀不安全。

### 升权

封闭阶梯：read-only → workspace-write/danger-full-access；workspace-write → danger-full-access。请求必须同时给出严格更宽的 `sandbox_permissions` 和 justification，且重试相同调用。审批只对这一次重试有效；不加宽或字段不配对时不提示人类，直接拒绝。

## 安全边界

- 该沙箱词汇只覆盖文件效果，不覆盖网络、设备、凭据、全部系统调用；
- 本地同用户隔离不等于容器/microVM；
- danger-full-access 只是明确关闭文件约束；
- 动态插件、Preset、Skill/Workflow 代码仍是受信任代码；
- 多租户需要替换执行 provider，并进行进程/网络/凭据隔离。

## 实现任务

1. Approval types/service/waterfall/policy；
2. asked/decided 事件和 invariant；
3. runtime-context policy snapshot；
4. Permission Preset table/current/custom/new-session pin；
5. SandboxPolicy/provider/unavailable error；
6. writable roots 和 path canonicalization；
7. escalation validation + Approval orchestration；
8. platform runner capability detection；
9. ToolRuntime ask/guard/sandbox 接线。

## 测试矩阵

| 场景 | 预期 |
|---|---|
| ask + allow/reject | 审计配对，结果一次有效 |
| 无 responder/抛错/非法返回 | unavailable、fail-closed |
| never + prepend responder | responder 不运行，确定拒绝 |
| abort 与回答竞速 | 首个有效结算，迟到回答丢弃 |
| Turn 外请求 | 审计前拒绝 |
| asked append/decided append 失败 | 不产生未审计允许 |
| preset/custom/no-op | 旋钮和选择事件正确 |
| 新会话/resume seed | 默认仅用于新会话 |
| path traversal/symlink | 不能越过 root |
| backend unavailable | SANDBOX_UNAVAILABLE，不执行原 argv |
| 严格升权/非升权/缺 justification | 只有合法加宽触发审批 |
| allowed-once 重试 | 只本次、更宽模式、同一调用 |
| secret redaction | 审批/日志无敏感原参数 |

## 完成标准

- 所有缺失/异常组件均 fail-closed；
- 审批事件严格配对且取消无迟到提交；
- 路径与升权故障测试通过；
- 文档明确本地沙箱不覆盖的威胁；
- Tool body 无法绕过审批/Guard/confine。
