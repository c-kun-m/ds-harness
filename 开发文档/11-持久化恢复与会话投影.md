# 11：耐久持久化、崩溃修复与增量会话投影

## 本课定位

逻辑 Session 已在 05 完成。本课增加 provider-independent Persistence seam、JSONL 后端和面向客户端的 Projection Registry。日志是唯一真源；投影/缓存可丢弃重建。

## 学习目标

- 区分 create、materialize、append、flush、load、inspect 和 readFrom；
- 保证 append 成功返回时批次已 durable；
- 用有界 write-behind 降低频繁 fsync，但保留显式 barrier；
- 处理首次发布、撕裂尾部、连续 seq 和并发 writer；
- 保留中断轮次并追加合成 closer；
- 建立同步纯折叠的 Projection Unit 与增量驱动；
- 明确 v0 格式兼容和拒绝方向。

## Persistence Service

### 创建与物化

- `create(meta, inheritedEventCount?)` 建立逻辑记录，可以保持惰性；
- seeded meta 必须携带精确 cut，unseeded 拒绝非零 cut；
- seeded 首次物化批次必须包含完整继承前缀，不能发布 cut 大于实际日志的 header；
- `ensureMaterialized(session)` 只在空会话也必须出现在列表时写 header，不虚构事件。

### 写入

- `append(id, events)` 只接受从存储 next seq 开始的连续批次；
- 先验证 lossless JSON 和事件/invariant；
- 成功返回表示批次已安全写入和同步；
- 失败保留待写事件，显式 flush 可重试；不能报告成功后再后台写。

### 读取

- `load`：返回不可变平衡日志，并提交必要的崩溃修复；
- `inspect`：读取同一完整视图，但不修改/提交修复；
- `readFrom(SessionLogOffset)`：返回明确 fromSeq、继承 cut 和后缀事件；
- `list`：只读轻量 header；
- `locate`：纯计算可定位产物，不执行 I/O。

活动 Session 的 load 先 flush snapshot，开放 Turn 时拒绝冷接管。HMR/多 owner 需要 revision/identity 防止陈旧准备结果。

## Write-behind 与 barrier

第一个事件开启固定最大批处理窗口，后续事件加入但不延长截止；写入中的新事件形成下一批。`session/flush` 取消等待并排空所有批次到停稳，将后台错误带回调用者。

语义 checkpoint 至少在：启动下一个模型请求前、关键外部副作用前、Goal 自动续行前、关闭/移交前。若 flush 失败，停止新副作用。

## JSONL 后端

推荐每 Session 独立安全目录。第一逻辑记录是私有 header，之后是事件/允许的 chunk pack record。Session id 必须单射转义为安全路径段。

### 首次发布

header + 首批通过临时产物/无覆盖原子 publish 并 fsync；并发 create 只有一个获胜。空会话只有 ensureMaterialized 才发布。

### 后续 append

追加整批，失败时截回之前字节长度。压缩关闭时是 UTF-8 JSONL；启用 Zstd 时使用独立可校验帧：header frame + 每批 append frame。一个 root 只能有一种编码，不混合回退。

### 崩溃修复

- 只丢弃从未完整提交的撕裂尾部/不完整最后 frame；
- 已校验前缀损坏、checksum/seq/结构错误拒绝；
- 保留已持久化的开放 Turn；
- 未持久 call 的 assistant request 合成 `TOOL_NOT_STARTED`；
- 已有 call 无 result 合成 `TOOL_OUTCOME_UNKNOWN`；
- 补 step/end、turn/end interrupted；
- load 把 closer 追加持久化，inspect 只展示不提交。

不确定副作用绝不自动重跑非幂等工具。

## 格式与兼容

固定基线 format v0。只规范化明确列出的同版本旧 record 变体；更高版本报 upgrade-required，更低不支持版本报 unsupported。未知必需事件拒绝，ignorable 才能跳过。没有通用“尽量解析”。

## Projection Registry

每个 Projection Unit 定义：

- key 和 wire schema；
- 初始 state；
- 同步 `apply(state,event)`；
- 同步 `view(state)`；
- 可选 state/view identity gate 避免无变化通知。

注册表可以全量 fold 冷日志，也可在 session/event 后逐事件推进 cell。投影不得阻塞、返回 Promise 或读取不一致外部状态。客户端 tail page/通知带 projection revision/seq，使快照与增量可衔接。

SQLite/Projection Cache 只保存可验证 checkpoint；revision 不匹配时回退全量重建，绝不反向修复 Session。

## 测试矩阵

| 场景 | 必须观察到 |
|---|---|
| lazy create/ensure materialized | 列表和磁盘语义正确 |
| seeded cut | 缺失/非法 cut 拒绝，首批前缀完整 |
| 连续 append/seq 缺口 | 前者 durable，后者拒绝 |
| write-behind 两批 | 固定窗口，不无限延迟 |
| append/flush I/O 失败 | 错误可观察，事件可按合同重试 |
| 首次发布竞争 | 不覆盖获胜者 |
| 撕裂尾部 | 只截未提交尾部，前缀保留 |
| 已提交前缀损坏 | corruption fail-closed |
| load vs inspect | 两者视图一致，仅 load 提交 repair |
| 未开始/结果未知工具 | 合成不同稳定 closer |
| active/open Turn load | flush/拒绝策略正确 |
| projection 全量 vs 增量 | view 完全相同 |
| cache revision stale | 放弃缓存并重建 |
| dispose 有在途写入 | 排空到停稳，无后台写 |

## 完成标准

- append/flush 的 durability 含义通过真实临时目录故障测试；
- 崩溃恢复不删已提交证据；
- TOOL_NOT_STARTED 与 TOOL_OUTCOME_UNKNOWN 分开；
- projection 全量/增量/缓存重建一致；
- teardown 无在途写入和文件句柄泄漏。
