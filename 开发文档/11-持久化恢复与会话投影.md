# 持久化、恢复与会话投影

## 目标

把内存 Session 变成耐久、可恢复的事件日志，并提供面向 Web/API 的读模型。先实现原始 JSONL，再加 SQLite 投影；两者职责不得互换。

## 前置条件

完成 [权限、审批与沙箱](10-权限审批与沙箱.md)。

## Persistence 接口

- `create(header)`：准备新会话，不一定立即写盘。
- `append(sessionId, expectedSeq, events)`：只追加连续事件。
- `flush(sessionId)`：达到耐久点后返回。
- `load(sessionId)`：返回验证后的 Header 和事件。
- `listSnapshots()`：轻量列出会话元数据和存储 revision。
- `inspect(sessionId)`：只读平衡视图，不修复文件。

## JSONL 布局

每个 Session 独立目录，第一行是 Header，后续每行一个事件。Session ID 必须编码为安全路径段；工作区路径只用于可读目录名，不能作为唯一标识。MVP 不压缩，格式稳定后再加 zstd frame。

## Durability Checkpoint

模型请求前、顶层工具 dispatch 前、Goal 自动续跑前和进程关闭前必须 `flush()`。Checkpoint 失败则停止当前工作并记录内存错误，不能继续产生外部副作用后假装已保存。

## 崩溃恢复

- 最后一行不完整时只截断该行。
- 已记录 `tool/call` 但没有结果时，恢复视图追加合成结果 `TOOL_OUTCOME_UNKNOWN`。
- 已形成模型请求但模型未完成时，记录可解释的 aborted/error 结束事件。
- 非幂等工具的 unknown outcome 不得自动重试；要求用户、业务幂等键或事实查询确认。
- 格式版本未知、seq 中断或已提交 Turn 之前损坏时拒绝加载。

## SQLite 投影

SQLite 保存 Session 列表、当前状态、标题、更新时间、父子关系、Goal/Todo/Plan 和本体执行摘要。投影保存最后消费 seq，可以从 JSONL 全量重建。禁止只更新 SQLite 而不写 Session 事件。

## 手写顺序

1. 实现原始 JSONL create/append/load/flush。
2. 实现同 Session 串行写协调器和批量 fsync。
3. 实现临时文件 + 原子无覆盖首次发布。
4. 实现尾部恢复和 unknown outcome 合成。
5. 实现 Session resume 事务。
6. 实现 Projection Registry 和 SQLite consumer。
7. 实现 projection rebuild 与 revision 校验。

## 测试与完成标准

使用真实临时目录测试首次创建竞争、连续追加、半行崩溃、重复 Writer、flush 失败、未知工具结果和投影重建。完成后，杀死一个正在执行假工具的子进程并重启 Runtime，UI 投影必须显示该调用结果未知而不是自动重跑。
