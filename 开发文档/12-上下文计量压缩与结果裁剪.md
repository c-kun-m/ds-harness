# 12：Token 计量、日志化压缩、工具配对与 Spill

## 本课定位

压缩改变模型 Surface，不删除原始 Session。它不是“把旧消息数组换成摘要”这么简单：需要日志化锁、闭合范围、工具 call/result 配对、失败回滚、并发注入和持久 checkpoint。超大工具结果先裁剪，再 spill，不能把 base64/大文本无界塞进事件和 WebSocket。

## 学习目标

- 估算完整请求 envelope 的 token 压力；
- 将压缩策略与抽象 Compaction seam 分离；
- 用 `compaction/start → summary → end` 日志标记作为锁和恢复证据；
- 选择不切断工具配对的 Surface 范围；
- 只进行一次 Surface replace，失败时旧 Surface 不变；
- 先裁剪大型工具结果，再安全 spill；
- 处理取消、过期锁、并发注入和 overflow。

## Token Meter

计量对象是完整请求：system prompt、tool schemas、runtime context、历史消息、预计输出，而不只是消息文本。精确 provider usage 作为后续校准事实写入日志，不反向改写旧估算。

策略按精确 provider/model 路由解析 context window、触发阈值、保留尾部和摘要输出上限。保留预算必须小于触发预算；数值是配置，不是永久核心常量。

## Compaction Seam

抽象服务至少提供：

- `compactIfNeeded`：pressure/context-overflow；
- `compactNow`：人工显式触发；
- `compactRegion`：调用方给定 Surface 范围。

Seam 只定义合同；basic backend 拥有选择策略和 LLM 摘要。摘要调用必须传 signal，Fiber dispose 会停止它。

## 日志锁和事件顺序

成功操作：

```text
append compaction/start      # 获取日志化锁，仅日志
→ 验证/选择平衡 Surface 范围
→ 生成摘要
→ append compaction/summary  # 记录摘要事实，仅日志
→ append one user/message with surface replace
→ append compaction/end      # 释放锁，仅日志
```

replace 位于 start/end 内。start 后崩溃会留下可检测锁，不会伪造成功 end。失败后恰好尝试一次带错误 end；若关闭本身失败，未配对 start 继续作为 busy/repair 证据。

活动锁只在当前 session lifecycle/seed 边界后判断；更早未配对 start 可分类为 stale crash evidence。锁期间无关 `inject()` 可能追加，因此手动路径切换前必须重新验证选中范围，不能要求整个 Surface 完全没变。

## 工具配对边界

压缩边界不能把 assistant tool call 与对应 tool result 分开，也不能把孤立 result 当普通节点。实现 `balancedBefore/After` 或等价 cache：

- 验证 seq 仍在当前 Surface generation；
- 缓存各切分点的工具配对状态；
- replace generation 变化后重建；
- missing seq/孤立 result 视为 Surface corruption；
- 重复边界查询不应每次全量扫描。

## 摘要与 Surface

摘要是带稳定 checkpoint marker/source 的 user-role message，包含目标、约束、已完成、关键事实/文件变化、失败、不确定副作用和待办。它替换选中范围，近期尾部保留。原始被遮蔽事件仍存在，回放确定。

压缩失败或摘要校验失败时不执行 replace；再次估算仍 overflow 时只进行有限恢复，不无限递归压缩。

## Tool Result Pruner

在通用历史压缩前，对巨型工具结果做类型感知裁剪：

- 保留错误、来源、首尾和关键定位；
- 维持 tool call/result 配对；
- 写 `compaction/prune`/等价审计记录，记录影子价格/删减证据；
- 不把裁剪后文本冒充完整原值；
- 图片/结构化值遵守各自持久引用合同。

## Spill Store

超过 inline limit 的原内容写 Session-owned spill：

- 不可猜测 identity、owner session、byte length、hash、media type；
- 原子写入和 hash 校验；
- 模型只看到有界摘要与受控读取引用；
- API 读取要校验 Session 权限，禁止路径穿越；
- retention/cleanup 是独立策略，不能在 Session 仍引用时提前删除；
- 大内容不复制进普通事件或实时通知。

## 实现任务

1. TokenMeter 和脚本化 meter；
2. CompactionEngine seam/error codes/checkpoint marker；
3. 工具配对边界 cache；
4. 日志锁、busy/stale 和 marker invariant；
5. basic region selection/summarizer/surface replace；
6. cancellation/failure close/overflow；
7. tool-result pruner；
8. spill store/授权/hash/retention；
9. 全流程重放与故障注入。

## 测试矩阵

| 场景 | 必须观察到 |
|---|---|
| 无压力/达到阈值 | no-op 或恰好一次 compact |
| 工具对边界 | 不在 call/result 中间切分 |
| 孤立 result/missing seq | corruption，不继续摘要 |
| 两次并发 compact | 一次获锁，另一次 busy |
| start 前取消 | 无 marker |
| start 后摘要/replace/end 失败 | 旧 Surface 或明确锁证据，无伪成功 |
| lock 中 inject | 切换前重新验证，保留无关输入 |
| 成功压缩 | 一次 replace，原事件全保留 |
| resume 未配对 start | active/stale 按生命周期分类 |
| 仍 overflow | 有限恢复后稳定失败 |
| pruner | 工具配对和错误信息保留 |
| spill 原子失败/hash mismatch | 不发布坏引用/读取拒绝 |
| 跨 Session 猜引用 | 授权拒绝 |
| replay | 相同日志得到相同摘要 Surface |

## 完成标准

- 锁/marker/工具配对 invariant 全部通过；
- 任一失败点不破坏旧 Surface；
- 原始日志永不因 compaction 删除；
- 大结果只通过有界摘要和授权引用进入模型；
- 取消/teardown 后无摘要流、spill 临时文件或未闭锁任务。
