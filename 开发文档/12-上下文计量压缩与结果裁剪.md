# 上下文计量、压缩与结果裁剪

## 目标

让长会话在模型窗口内继续运行，同时保留完整原始事件用于审计。压缩改变模型表面，不删除事实日志。

## 前置条件

完成 [持久化、恢复与会话投影](11-持久化恢复与会话投影.md)。

## Token Meter

`TokenMeter.estimate(request)` 返回系统提示词、工具 Schema、消息和计划输出的估算 Token。精确 Provider 使用量在流结束后写回事件，用于校准但不反向修改历史估算。

## Compaction Policy

默认可以参考 DSH：使用达到上下文窗口 80% 时触发，保留最近约 16%，摘要输出上限 8192，普通压缩和 overflow 恢复各重试一次；这些必须是可配置值，并允许精确 provider/model 覆盖。保留预算必须小于触发预算。

## 压缩流程

1. 在发起模型请求前计算压力。
2. 选择闭合的历史范围，不能切断工具 call/result 或 Turn。
3. 用独立摘要请求生成结构化摘要：目标、已完成工作、关键事实、文件变化、失败、未决项和约束。
4. 写入 compaction 事件和摘要消息。
5. 通过 surface `replace-range` 让模型看到摘要加保留尾部。
6. 再次估算；仍溢出时执行有限 overflow 恢复，超过上限则失败。

## 工具结果裁剪与 Spill

大工具结果先由工具结果 Pruner 根据类型保留首尾、错误和关键定位；仍超过 inline byte 限制时写入 Session-owned spill 文件，并在模型结果中保留摘要、哈希、字节数和可读取引用。原始内容不得塞进普通日志字段或 WebSocket 通知。

## 手写顺序

1. 实现 TokenMeter 接口和脚本化 Meter。
2. 实现按闭合 Turn 选择压缩范围。
3. 实现摘要 Schema、摘要 Adapter 调用和 surface replacement。
4. 实现重试、失败和并发压缩锁。
5. 实现工具结果 Pruner。
6. 实现 Spill Store、完整性哈希、授权读取和清理策略。

## 关键不变量

- 摘要和保留尾部不能重复表达同一工具结果。
- 压缩失败不破坏旧模型表面。
- 原始事件永远保留；删除策略属于单独的数据保留功能。
- 模型路由变化后按新路由上下文窗口重新解析策略。
- Spill 引用受 Session 权限保护，不能通过路径猜测读取其他会话。

## 测试与完成标准

用小上下文窗口的假模型强制多次压缩，验证工具配对、摘要范围、失败回滚、overflow 上限和恢复重放。完成后，一个超过 inline 限制的工具结果只向模型暴露摘要和引用，但审计端可校验并读取原内容。
