# 本体模型与事实存储

## 目标

建立可版本化、可验证、可查询的领域模型和事实状态，为工具筛选、动作前置条件、执行回写和审计提供确定性数据源。MVP 不实现通用 OWL 推理器，而是实现面向业务 Action 的强类型本体内核。

## 前置条件

完成 [上下文计量、压缩与结果裁剪](12-上下文计量压缩与结果裁剪.md)。

## 数据模型

- `OntologyVersion`：ID、语义版本、状态 draft/active/retired、内容哈希、创建时间、上一个版本。
- `EntityType`：类型 ID、属性定义、唯一键、父类型、敏感字段标签。
- `RelationType`：关系 ID、from/to 类型、基数、方向和删除策略。
- `Constraint`：required、enum、range、pattern、unique、relation cardinality 和自定义表达式 AST。
- `EntityInstance`：实例 ID、类型、属性、revision、有效时间。
- `RelationInstance`：关系实例、两端实体、revision、有效时间。
- `Fact`：主语、谓词、宾语或标量值、来源、置信度、revision、有效区间和状态 asserted/retracted。
- `FactSnapshot`：一个原子读取的 ontologyVersion + factRevision，用于策略判定和执行 CAS。

## 存储接口

`OntologyRepository` 管理定义版本；`FactStore` 管理实例和事实；`OntologyQuery` 在一个 Snapshot 上执行类型、关系和条件查询；`OntologyPort` 聚合这些接口，使未来可以替换为 `euos-service-j` 远程实现。

## 手写顺序

1. 定义本体 JSON Schema 和 Zod Schema，所有引用使用稳定 ID。
2. 实现 draft 加载和完整性校验：引用存在、继承无环、关系端类型正确、约束可解析。
3. 实现版本发布；active 版本不可原地修改，新版本必须生成新 ID/哈希。
4. 实现内存 FactStore 和 revision CAS。
5. 实现 SQLite 表和事务，保留每次事实变更的 append-only history。
6. 实现 Snapshot 查询和敏感字段脱敏视图。
7. 实现本体迁移校验报告，但 MVP 不自动迁移不兼容实例。

## 一致性规则

- 一个策略判定只读取一个 FactSnapshot，不能跨 revision 拼装结果。
- 所有事实都记录来源：human、tool、business-system、inference 或 migration。
- 推断事实不能覆盖原始事实；它们用独立来源和规则 ID 表示。
- 删除使用 retract/tombstone，不在审计历史中物理消失。
- 本体版本和事实 revision 都进入后续 Policy Decision 事件。

## 与 Session 的关系

FactStore 是领域状态真源，Session 是 Agent 执行和决策审计真源。事实事务成功后，通过 Outbox 生成 `ontology/facts-committed` Session 事件；如果 Session 追加失败，Outbox 保留待投递记录。禁止一个普通工具先写业务状态、再尽力写 Session 的非原子双写。

## 测试

- 非法引用、继承环、基数和类型冲突。
- 同 revision 并发更新只有一个成功。
- Snapshot 查询在并发写入期间保持一致。
- 发布后定义不可变，版本哈希可复算。
- Outbox 重试不重复应用事实变化。
- 敏感属性不出现在模型 Context 和普通日志中。

## 完成标准

创建一个“工单—负责人—状态”小本体，发布版本，写入实体和关系，按 revision 查询并更新工单状态；重启后历史、当前快照和内容哈希保持一致。

## DSH 参考与差异

DSH 没有对应本体包。本模块只借用 [Session 事件化原则](../deepseek-harness/docs/architecture.md#session-log)和 [SQLite 存储分层](../deepseek-harness/packages/storage/storage-sqlite/README.md)，不能把 [mcp-memory](../deepseek-harness/examples/mcp-memory/README.md)当成本体实现。
