# 本体动作映射与策略判定

## 目标

把领域 Action、工具实现和确定性规则连接起来，使本体决定当前 Step 的候选工具，并在真正执行前再次验证权限和前置条件。

## 前置条件

完成 [本体模型与事实存储](13-本体模型与事实存储.md)。

## ActionDefinition

每个 Action 包含：`actionId`、版本、输入 Schema、可作用实体类型、前置条件表达式、后置条件模板、Tool Name、风险等级、所需权限、幂等策略、可选补偿 Action、对模型公开的简短语义说明。Action ID 是业务语义，Tool Name 是执行实现，二者不能混为一个字段。

## 规则表达式

MVP 使用受限 JSON AST，不执行任意 JavaScript。节点只支持 `and`、`or`、`not`、比较、集合包含、类型判断、关系存在、事实查询和调用者权限。所有表达式在 Action 发布时类型检查；运行时只读取一个 FactSnapshot。

## 三个判定点

### 候选生成

在 Prompt Assembly 前，根据用户/Agent 身份、目标实体、FactSnapshot 和 Action 前置条件生成 `ActionCandidate[]`。只有候选 Action 对应的工具进入当前模型请求。

### 计划验证

模型提出结构化 Action 或计划节点后，验证 Action 存在、输入符合 Schema、依赖合法、调用者可见，并生成不可变 `PolicyDecision`。

### 执行 Guard

工具真正 dispatch 前重新读取最新 Snapshot，再次验证 Action、参数、身份、权限和前置条件。候选时允许不代表执行时仍允许；状态变化必须 fail closed。

## PolicyDecision

记录 decisionId、Session/Turn/Step/Call ID、Action ID、Tool Name、输入摘要哈希、ontologyVersion、factRevision、matchedRuleIds、allow/deny、原因码和时间。敏感值不直接写入事件，必要时写受控 artifact 引用。

## 手写顺序

1. 定义 Action Schema 和表达式 AST。
2. 实现发布期引用解析和静态类型检查。
3. 实现纯函数 `evaluate(expression, snapshot, subject, input)`。
4. 实现 Action → Tool 映射注册，启动时拒绝未知工具和重复映射。
5. 实现 Candidate Generator，并通过 Tool `restrict()` 同时控制可见性和执行查找。
6. 在 Tool Runtime 的单调 Guard 中实现执行前重检。
7. 追加 `ontology/policy-decision` 事件，并向模型返回可操作的拒绝原因。

## TOCTOU 与事务

Guard 的 `factRevision` 随执行请求传给业务工具。业务写入必须使用该 revision 或领域幂等键做 CAS；如果状态已变化，工具返回 conflict，Runtime 不得把旧判定当作成功。长时间审批结束后必须重新运行 Guard。

## 关键不变量

- Prompt 隐藏和执行拒绝使用同一 Action/Tool 映射真源。
- 审批只能在本体允许后进一步授权，不能覆盖本体 deny。
- Policy evaluator 是无副作用纯函数；事实变化由执行结果回写模块完成。
- 每次 deny 都有稳定 reason code；模型不能通过改名或直接 Call ID 绕过。

## 测试与完成标准

覆盖允许、拒绝、缺事实、权限不足、审批期间 revision 变化、工具映射缺失和表达式类型错误。完成演示：只有状态为 `draft` 且当前用户为负责人时暴露 `submit_ticket`；状态或负责人变化后，执行 Guard 拒绝旧调用。
