# 14：Action 映射、候选生成与执行前确定性策略

## 本课定位

模型负责从自然语言中提出可能动作；本体策略负责决定它现在能看见什么、计划是否有效、真正 dispatch 时是否仍允许。候选可见性不是安全边界，执行前 Guard 才是最终确定性门禁。

这是本项目原创扩展，但必须通过 07 的 ToolRuntime 和 09 的 assembly 接入，禁止旁路。

## 学习目标

- 将业务 Action identity 与 Tool implementation identity 分开；
- 定义受限、可静态类型检查的规则 AST；
- 在同一 FactSnapshot 上纯函数评估；
- 复用同一 Action registry 驱动可见性和执行 Guard；
- 处理 candidate→approval→dispatch 期间事实变化；
- 产生无敏感值、可解释、可关联的 PolicyDecision；
- 对 deny、conflict、missing fact 和 internal error 使用不同稳定原因。

## ActionDefinition

至少包含：

- actionId + actionVersion；
- input schema 和适用 EntityType；
- precondition AST；
- postcondition declaration/template；
- toolName + tool contract version；
- risk level、required permissions；
- idempotency classification/key strategy；
- execution mode（parallel-safe/exclusive/domain-keyed）；
- optional compensationActionId；
- 面向模型的短描述和参数呈现规则；
- 敏感输入 redaction/hash policy。

Action 是业务语义，Tool 是执行适配器。同一 Action 可以换 Tool 实现；一个 Tool 也可能被多个受限 Action 包装，但映射必须无歧义。

## 规则 AST

MVP 允许：and/or/not、typed comparison、set membership、exists/missing、entity type、relation existence/count、fact query、caller roles/permissions、input field reference。禁止任意 JavaScript、网络、时间随机数和运行时修改事实。

发布期类型检查：

- 每个 path 在 input/entity schema 中存在；
- 比较两侧类型兼容；
- relation 两端类型符合定义；
- 操作符和函数属于封闭词汇；
- rule/action 引用无环或按明确策略处理；
- 所有 deny/allow branch 有稳定 rule id。

运行 evaluator 是纯函数：输入 snapshot、subject/caller、action input，输出 matched rule evidence 和允许/拒绝，不写日志/事实。

## 三个判定点

### 1. Candidate Generation

在 request assembly 前：

1. 解析目标实体/调用者范围；
2. 取得一个 FactSnapshot；
3. 对可用 Action 做前置评估；
4. 生成 ActionCandidate（action/tool/schema/说明/decision evidence）；
5. 用 Tool restrict/scoped registration 控制当前 Agent 可见 schema；
6. 记录 candidate snapshot/revision，供审计而非执行授权。

解析不出实体时可以提供澄清/只读发现 Action，但不能把所有写动作默认公开。

### 2. Plan/Proposal Validation

模型提出 action/plan 节点后：验证 action/version、输入 schema、实体、依赖和 caller visibility；产生不可变 validation decision。它仍不是执行授权。

### 3. Pre-dispatch Guard

在 Tool body 真正启动前：

1. 重新取得最新 Snapshot；
2. 重新解析 action↔tool 映射和输入；
3. 重新评估 caller、permission、preconditions；
4. 若审批曾等待，再次重检；
5. allow 时把 factRevision、decisionId、idempotency key 交给工具；
6. deny/conflict 时 body 不运行。

Guard 单调：审批只可在 ontology allow 后进一步拒绝/允许一次风险，不能推翻 ontology deny。

## PolicyDecision

记录：decisionId、stage（candidate/plan/dispatch/postcondition）、Session/Turn/Step/Call、Action/version、Tool/version、input digest/redacted summary、ontologyVersion、factRevision、caller/subject refs、matched rule ids/evidence refs、allow/deny、reason code、时间。

稳定 reason 至少区分：unknown-action、mapping-missing、input-invalid、fact-missing、precondition-false、permission-denied、revision-conflict、ontology-version-mismatch、policy-error。

原始敏感输入不进入事件；低熵值不能仅靠 hash 保护，优先 redacted summary + 受控 artifact 引用。

## TOCTOU 与事务

Guard allow 只证明 revision R 的状态。业务工具写入必须把 expected R/相关实体 revision 和 idempotency key 交给领域事务：

- 若事实未变，CAS 执行；
- 若无关事实变化但依赖集合可证明未变，可以用更细粒度 read-set/version（进阶）；
- 若冲突，工具返回 conflict，不能伪成功；
- Runtime 根据策略重新评估/重规划，不盲重试非幂等副作用。

## 映射 Registry 生命周期

Action→Tool 注册归 Scope Effect；启动时验证 ToolDefinition 存在、schema 兼容、action/version 唯一。Tool HMR 后 contract version 不兼容时暂停相关 Action，不继续使用旧假设。旧 disposer 不移除新映射。

## 实现任务

1. Action schema/version/registry；
2. Rule AST parser/type checker；
3. pure evaluator 和 evidence；
4. mapping registry + tool schema compatibility；
5. Candidate Generator + assembly/tool restrict；
6. proposal validation；
7. monotonic pre-dispatch Guard + approval recheck；
8. PolicyDecision event/redaction；
9. CAS/idempotency execution context；
10. “draft 工单只有负责人可提交”演示。

## 测试矩阵

| 场景 | 必须观察到 |
|---|---|
| AST path/type/operator 错误 | 发布期全部拒绝 |
| allow/deny/missing fact | 稳定 evidence/reason |
| candidate 隐藏 | schema 与执行查找都不可见 |
| 恶意直呼隐藏 tool | body 不运行 |
| action/tool 映射缺失/冲突 | 启动/更新 fail-closed |
| candidate 后事实变化 | dispatch Guard 用新 revision 拒绝 |
| 审批等待期间变化 | 审批 allow 后仍重检拒绝 |
| 并发 CAS | 一次成功，冲突不伪成功 |
| ontology/tool version HMR | 不兼容 Action 暂停/失败 |
| sensitive input | decision/event 无原值 |
| evaluator exception | policy-error 且 body 不运行 |
| 两 Agent/Scope | 候选和 caller 权限互不污染 |

## 完成标准

- 同一 registry 驱动候选与 dispatch mapping；
- 审批/状态变化 TOCTOU 测试通过；
- 每个 deny 可解释且不泄密；
- 工具无法绕过 CAS/idempotency context；
- evaluator 无副作用并可对相同 Snapshot 重放。
