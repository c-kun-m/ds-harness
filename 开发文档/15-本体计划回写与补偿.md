# 15：持久 Action 计划、事实回写、补偿与重规划

## 本课定位

本课把用户目标编译为可持久、可恢复的 Action DAG，并驱动节点经过 14 的 Guard 和 07 的 ToolRuntime。它不是 Plan Mode 的软提示，也不是 Workflow 的临时 JavaScript；计划、节点、幂等、事实 revision、结果和补偿都是领域真相。

## 学习目标

- 区分模型 PlanProposal 与权威 OntologyPlan；
- 编译、验证并持久化 DAG；
- 用状态机和事件驱动 ready/running/terminal；
- 对并行节点保持依赖与领域冲突约束；
- 将工具结构化结果映射为 FactMutation；
- 通过 CAS + Outbox + 后置条件确定成功；
- 用 Saga 逆依赖补偿，不承诺全局数据库回滚；
- 崩溃恢复时区分 not-started、outcome-unknown、committed；
- 在最新 Snapshot 上增量重规划，不重复已确认副作用。

## 计划模型

### OntologyPlan

包含 planId、goal、ontologyVersion、createdFactRevision、caller/subject、state、nodes、policy metadata、revision 和 timestamps。

Plan state 建议：draft/validated/running/succeeded/failed/compensating/compensated/blocked/cancelled。转移封闭；blocked 需要 blocker code/evidence 和人工恢复方式。

### PlanNode

包含 nodeId、actionId/version、validated input、dependency ids、可选 typed condition、execution mode/domain lock key、state、attempt、idempotency key、last decision/execution/result/fact revision、compensation state。

Node state 至少：pending/ready/running/succeeded/failed/blocked/compensating/compensated/skipped/cancelled/outcome-unknown。`outcome-unknown` 不能自动变 failed 后重试。

## PlanCompiler

模型只产生不可信 Proposal。编译器：

1. 校验 Proposal schema/size；
2. 解析每个 Action/version 和 input；
3. 验证 dependency 存在、无环、条件类型；
4. 验证 caller/subject visibility 和初始 policy；
5. 解析 compensation mapping；
6. 生成稳定 node id/idempotency key；
7. 固定 ontology/action/tool contract versions；
8. 原子持久 validated plan。

能由确定规则直接生成的步骤不强制调用模型。Proposal 文本不是权威 plan。

## Scheduler

ready 条件：所有 required dependencies succeeded/符合允许的 skipped，condition 在最新允许 Snapshot 上为真，节点未终止。Scheduler 只从持久状态计算 ready，不用内存数组作为真源。

并发：

- parallel-safe 且领域 lock key 不冲突可进入有界池；
- exclusive 节点形成屏障；
- 依赖汇合在所有 required parent committed 后才 ready；
- cancel 关闭新 dispatch，已启动节点收敛；
- 状态 commit 顺序和 execution identity 确定。

## 节点执行事务

```text
persist node ready/running + attempt + idempotency key
→ flush/checkpoint
→ ontology dispatch Guard（最新 Snapshot）
→ ToolRuntime.execute
→ validate canonical structured result
→ pure result-to-FactMutation mapping
→ domain transaction: CAS + business effect record + fact history + outbox
→ read new Snapshot and verify postconditions
→ persist node succeeded with execution/fact revision
```

工具返回 success 但 mutation 或 postcondition 失败，节点不能标 succeeded。不要为了通过后置条件伪造事实。

若真实业务副作用不在同一数据库：使用业务 idempotency key、provider receipt 和查询确认，把 side-effect commit 与 fact projection 的中间状态明确记录；无法确认时进入 outcome-unknown/blocked。

## Result Mapping

Action 定义的 mapping 是受限模板或版本化纯函数：输入只包含验证后的工具 canonical result、原 input 和 Guard snapshot refs；输出是 FactMutation batch。mapping 不执行 I/O，不直接 append Session。结果和 mutation 分别校验，保留 mapper version/hash。

## Retry

只有稳定分类允许时重试：

- before-dispatch/not-started 可安全重新尝试；
- idempotent + 同 key 可按 provider 合同重试；
- conflict 重新 Guard/可能 replan，不直接重复旧写；
- outcome-unknown 非幂等节点必须查询、对账或人工确认；
- attempt/max/backoff 持久化，进程重启不重置预算；
- 不因 listener/投影暂时失败重复业务副作用。

## 补偿（Saga）

只有显式 compensationAction 才能自动补偿。选择已经 committed succeeded 且尚未补偿的节点，按逆依赖/逆拓扑顺序：

1. 编译 compensation input；
2. 重新 Guard/审批；
3. 用独立但稳定 idempotency key 执行；
4. 回写补偿 FactMutation；
5. 验证 compensation postcondition；
6. 持久 compensated。

补偿失败/未知进入 blocked，停止无限循环。补偿是新业务动作，不是删除原日志/事实历史。

## Replan

读取最新 Snapshot、当前 plan revision、所有 committed/unknown 节点：

- 已 succeeded 且后置条件仍成立的节点锁定，不重复执行；
- 已补偿节点作为历史约束；
- unknown 节点先加入确认/人工 blocker；
- 新 Proposal 只生成增量变更；
- merge 检查 node/action/version/依赖，不覆盖运行中节点；
- 每次 replan 增加 plan revision 并记录来源。

## 持久事件与恢复

状态可以存领域表，同时向 Session 投递关联事件。至少记录 plan created/validated/state、node state/attempt/decision/execution/result、mutation committed、compensation、replan、blocker。

恢复时从领域真源 + Session/outbox 对账：running 且无 dispatch 证据 → not-started；有 dispatch 无权威 receipt → outcome-unknown；domain transaction 已有 execution/idempotency receipt → 重建 succeeded/待 postcondition finalize，不重新执行工具。

## 测试矩阵

| 场景 | 必须观察到 |
|---|---|
| 缺节点/环/错误条件类型 | compile 拒绝，无权威 plan |
| 并行分支 + 汇合 | 允许重叠，汇合等待 committed parents |
| exclusive/domain key | 冲突节点不重叠 |
| Guard deny/revision conflict | body 不运行或 mutation 不提交 |
| 工具 success + result schema fail | 节点失败，不写事实 |
| mutation CAS fail | conflict/replan，不伪成功 |
| postcondition fail | 不标 succeeded，进入策略分支 |
| retry 进程重启 | attempt/budget/idempotency 不重置 |
| 非幂等 outcome unknown | 不自动重试 |
| 部分成功后失败 | 逆依赖补偿已成功节点 |
| 补偿失败/未知 | blocked，无无限循环 |
| replan | 保留仍成立成功节点，不覆盖运行中/unknown |
| commit 后事件前崩溃 | outbox/reconcile 恢复，不重复副作用 |
| cancel | 关闭新节点、已启动停稳、计划终态明确 |

## 完成标准

- 计划全状态和恢复路径可从持久证据重建；
- non-idempotent unknown 不会自动重跑；
- mutation/postcondition 决定成功，不以工具 `isError=false` 单独决定；
- 补偿有界、可审计、失败转 blocked；
- 演示中每个 decision、execution、fact revision 和 compensation 可追踪。
