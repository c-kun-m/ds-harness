# 本体计划、回写与补偿

## 目标

把用户目标转换为可持久化的 Action DAG，逐节点执行并将结果写回事实状态；失败时根据明确策略重试、补偿或重新规划。这个模块是确定性执行器，不等同于普通 Workflow 脚本或 Plan Mode。

## 前置条件

完成 [本体动作映射与策略判定](14-本体动作映射与策略判定.md)。

## 计划模型

`OntologyPlan` 包含 Plan ID、目标、ontologyVersion、创建时 factRevision、状态、节点和审计元数据。`PlanNode` 包含 Node ID、Action ID、参数、依赖节点、可选条件、状态 pending/ready/running/succeeded/failed/compensating/compensated/blocked，以及 attempt 和幂等键。

## 计划生成

模型只生成 `PlanProposal`，不直接获得执行权。`PlanCompiler` 验证所有 Action、参数、依赖、无环性、条件类型、补偿映射和调用者权限，然后生成固定的 `OntologyPlan`。确定性规则能够直接生成的节点不调用模型。

## 执行流程

1. 选择所有依赖已成功且条件为真的 ready 节点。
2. 按 Action 并发策略启动，写入 running 事件和幂等键。
3. 执行前再次调用本体 Guard。
4. 工具成功后先验证结果 Schema，再计算 Fact Mutation。
5. 在同一领域事务中应用 CAS、写业务结果和 Outbox。
6. Outbox 投递 Session 事件后，节点进入 succeeded。
7. 冲突、拒绝和失败按策略进入 retry、blocked、replan 或 compensation。

## 结果回写

每个 Action 定义从工具结构化结果到 Fact Mutation 的映射。映射是受限模板或纯函数插件，输入和输出都经过 Schema。后置条件在新 Snapshot 上验证；工具返回成功但后置条件不成立时，节点仍失败，不能伪造事实使其通过。

## 补偿

采用 Saga 语义，不承诺数据库级全局回滚。只有 Action 显式声明补偿映射时才可自动补偿。补偿按已成功节点的逆依赖顺序执行，每次仍经过 Guard、审批、幂等和审计。补偿失败后计划进入 blocked，等待人工处理，禁止无限循环。

## 重新规划

replan 读取最新 Snapshot 和已完成节点，生成增量 Proposal。已经成功且后置条件仍成立的节点不能重复执行；outcome unknown 的非幂等节点必须先查询或人工确认。

## 手写顺序

1. 定义 Plan/Node 事件和投影状态机。
2. 实现 DAG 校验、拓扑排序和 ready 选择。
3. 实现 PlanCompiler 和结构化模型输出 Schema。
4. 实现节点执行器和并发上限。
5. 实现结果映射、CAS、Outbox 和后置条件验证。
6. 实现重试分类、补偿栈和 blocked 状态。
7. 实现 replan 合并和人工恢复命令。

## 测试与完成标准

覆盖环、缺依赖、条件分支、并发汇合、CAS 冲突、幂等重试、后置条件失败、部分成功补偿、补偿失败和进程中断恢复。完成演示：创建工单→分配负责人→提交；第二步失败时撤销已创建工单，所有决策和事实 revision 可审计。

## DSH 参考与差异

可借鉴 [Workflow Engine](../deepseek-harness/packages/workflow/workflow/README.md)的隔离执行和 [Goal Driver](../deepseek-harness/packages/goal/goal-round-driver/README.md)的续跑边界，但本模块必须持久化 DAG、节点状态、幂等键、事实 revision 和补偿结果。
