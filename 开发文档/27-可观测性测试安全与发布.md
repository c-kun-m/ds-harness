# 27：运行时不变量、测试矩阵、安全审查与发布门禁

## 本课定位

本阶段不再新增业务表面，而是证明前 26 个模块在正常、失败、并发、重入、崩溃和攻击输入下仍满足合同。可观测性不能泄密；运行时 invariant 应检查包拥有的真实关系，不重复单元测试纯函数。

## 学习目标

- 建立统一 log/metric/trace 和 redaction；
- 每个有状态包拥有自己的 invariant companion；
- 建立 unit/property/integration/snapshot/E2E/fault/parity 分层；
- 将固定上游行为映射为黑盒 parity；
- 完成威胁模型和 fail-closed 测试；
- 版本化 Session/Ontology/Protocol/Artifacts；
- 在干净环境验证构建、安装、迁移、回滚和关闭；
- 生成 SBOM、许可证和发布证据。

## 可观测性

### Structured Log

字段按事件需要选取：request/session/agent/turn/step/call/action/plan/node/job/subagent/workflow/provider/epoch/generation、phase、duration、stable error code。不要把 Prompt、工具原参数、完整结果、API key、approval secret、Fact sensitive value 默认日志化。

统一 redactor 处理深层对象、Error cause、header/env/URL query；日志 sink 失败不能破坏核心状态机，但要有本地诊断/计数。

### Metrics

LLM request latency/failure/tokens/retry；tool policy/approval/dispatch/duration/timeout；Agent inbox/turn/step；persistence batch/flush/repair；compaction/prune/spill；MCP connection/reconnect/generation；Jobs/Subagent/Workflow active；ontology allow/deny/CAS/conflict/compensation；Web stream/backpressure/reconnect。

维度必须有低基数策略，不能把 SessionId/ToolCallId 当 metrics label。

### Trace

层级可为 Session/Turn/Step/LLM/Tool/Action/Mutation/Child Run。跨 worker/process 显式传 trace context；AsyncLocalStorage 只进程内。默认不上传内容，只上传稳定 identity/phase/size/duration/status。

## Runtime Invariant Registry

Registry 本身与产品无关；包通过 `./invariant` companion 以精确 package name 注册 installer：

- companion 检查该包拥有的持久事件关系或可变 snapshot；
- 不检查“某方法存在”“某纯函数返回固定值”等单测问题；
- installer 在专用 child Fiber setup，失败原子回滚；
- package allow/block filter 只选择检查，不改变产品行为；
- 会话型 invariant 从历史重建 baseline，纯实时 invariant 明确会漏 reload 前操作；
- InvariantError 带稳定 code + owner package；
- companion 自身 listener 生命周期归 Effect，卸载无残留。

至少覆盖 Session 配对、LLM 流语法、Tool pipeline stage/frozen result、Agent 状态/Input、Scope carrier、Compaction markers、Approval pairs、Goal fold/prompt、Workflow/Subagent pairs、Todo/Plan payload、本体 decision/mutation/plan 状态。

## 测试分层

| 层 | 目标 | 禁止替代 |
|---|---|---|
| Unit | 纯函数、状态转移、schema、错误映射 | 不证明真实 I/O |
| Property | JSON/事件 fold、DAG、任意操作序列、不变量 | 不依赖随机碰到所有竞态 |
| Deterministic concurrency | deferred/barrier 控制精确交错 | 禁止 sleep 猜顺序 |
| Integration | 文件、SQLite、子进程、Worker、WebSocket、MCP server | 不直接调用内部函数跳过 seam |
| Snapshot | Prompt/tool schemas/user-visible stable text | 不锁堆栈/易变内部格式 |
| E2E | CLI/SDK/Web/ACP 真实组合 | 不用 mock 绕过主入口 |
| Fault injection | 磁盘满/半写/断网/crash/listener fail/timeout | 不只测试抛 Error |
| Real API | DeepSeek adapter 兼容和能力 | 无 key 可跳，不替代 scripted adapter |
| Parity | 固定上游代表性黑盒行为 | 不逐行复制上游实现 |

## 跨模块故障演练

至少自动化以下场景：

1. Effect setup 内卸载、清理失败、旧 disposer 晚到；
2. LLM 流中断/finish 后 chunk/API key redaction；
3. tool body 已分发后进程 crash → outcome unknown；
4. approval allow 与 fact revision 变化竞态；
5. persistence append/flush/fsync/rename/truncate 失败；
6. compaction start 后 crash/end 失败；
7. Goal reserve 后 human input/flush failure/unload；
8. Subagent publish/parent offline/cold restore/teardown；
9. Workflow Worker hang/crash/child non-cooperation；
10. MCP tools/list generation conflict/reconnect exhaustion；
11. Web reconnect journal gap/slow consumer；
12. Ontology domain commit 后 Session outbox 投递前 crash；
13. Saga compensation fail/outcome unknown；
14. shutdown 时同时有 LLM/tool/job/subagent/write/stream。

## 威胁模型

### 信任边界

区分：用户文本、模型输出、工具参数、Skill/Prompt 内容、受信插件代码、MCP server、业务 service、浏览器 client、ACP/SDK automation、filesystem/process/network、持久文件。每条跨界都有 schema、授权、大小、取消和审计。

### 至少覆盖

- Prompt injection 诱导越权；
- 隐藏工具直呼/名称混淆/MCP namespace collision；
- JSON/schema prototype/unknown-field/oversize；
- directory traversal/symlink/TOCTOU/read-before-write；
- shell argv/env injection/secret inheritance；
- sandbox unavailable/runner spoof/escalation replay；
- approval double answer/late answer/request id reuse；
- WebSocket Session owner/CSRF/origin/token leakage；
- SSRF/redirect/header leak/恶意 MCP content/image；
- non-idempotent retry/outcome unknown；
- cross-Session Job/Spill/Subagent/Fact access；
- Workflow/Skill dynamic instruction escape；
- log/error/trace/metrics secret leakage；
- dependency/package/plugin supply chain。

每项有 attack test、当前防护、残余风险和用户文档。不能只写“由沙箱保护”。

## 数据、格式与迁移

- Session、ontology、protocol、spill/export 各自有独立版本；
- 高版本拒绝要指明 upgrade；低版本仅支持列出的迁移；
- migration 先验证/备份，写新产物后原子切换，失败保留原件；
- export 带版本 manifest、hash、lineage 和敏感数据策略；
- import 先全量验证，不边读边写权威存储；
- retention/delete 覆盖 Session、Spill、附件、Facts、projection/cache，并按引用顺序；
- 删除与审计/法律保留冲突时由显式 policy 决定。

## CI 门禁

每提交：format/lint/typecheck/unit/link check/diff check；核心改动增加 concurrency/property/invariant/parity。主分支：integration、build smoke、coverage、secret scan、dependency/license audit。发布候选：Playwright、SDK/ACP、跨平台 sandbox、fault suites、upgrade/downgrade、clean install、shutdown leak、real provider smoke。

文档门禁检查：所有相对链接、固定上游 commit、术语、每课测试矩阵和差异账本；生成 schema/catalog 与源码一致。

## 发布流程

1. 冻结协议/格式/上游 parity baseline；
2. 生成 SBOM、第三方许可证、锁文件报告和 provenance；
3. 构建 Runtime/Web/SDK/ACP，干净目录安装 smoke；
4. 新数据目录首次启动；
5. 上一支持版本创建数据，当前版本 load/migrate/rollback 演练；
6. 执行威胁清单、fault suite、shutdown leak；
7. 生成 release notes：功能、breaking、migration、known limits；
8. 发布 candidate/canary，观察；
9. 正式发布；协议问题优先修合同，不用客户端特判掩盖。

## 完成标准

- 所有关键事件关系有 owner invariant 或解释不适用；
- 故障矩阵可重复，无 sleep 偶然性；
- threat model 每项有测试/残余风险；
- secret scan 和人工采样无内容泄漏；
- 迁移失败保留旧数据；
- shutdown 无 Worker/child/socket/file/timer/listener/pending rejection；
- 发布证据可在干净环境复现。
