# 可观测性、测试、安全与发布

## 目标

把各模块的局部验收提升为发布级质量门禁。这个阶段不再添加新业务能力，只补齐运行诊断、系统测试、威胁模型、数据保留和发布流程。

## 前置条件

完成 [Web 控制台](26-Web控制台.md)。

## 手写顺序

1. 先定义统一 Logger、Metric 和 Trace 接口以及脱敏器，再让各模块接入，禁止散落 `console.log`。
2. 补齐单元、属性、集成和 Snapshot 测试矩阵，把每个已知恢复分支固定下来。
3. 建立从真实 CLI/Web/SDK 入口运行的 E2E 场景和测试数据工厂。
4. 增加磁盘、网络、进程、Provider 和审批故障注入。
5. 编写威胁模型，逐项增加防护测试和用户可见限制说明。
6. 固定格式版本、迁移、导出、保留和删除策略。
7. 最后建立 CI、构建产物 smoke、SBOM 和发布候选流程。

## 可观测性

结构化日志至少包含 requestId、sessionId、turn、step、callId、actionId、planId、jobId 和 duration；敏感字段经过统一 redaction。指标包含模型请求耗时/失败/Token、工具耗时/拒绝/超时、队列长度、Compaction、持久化延迟、MCP 重连、Job 和子 Agent 数量、本体 Policy allow/deny/CAS conflict。Trace 以 Session/Turn/Step/Tool/Action 为 Span 层级，但不得把 Prompt 和 Secret 默认上传。

## 测试分层

| 层 | 重点 |
|---|---|
| 单元测试 | 状态机、Schema、规则求值、DAG、错误分类 |
| 属性测试 | 任意事件重放、并发顺序、JSON 往返、DAG 无环和 CAS |
| 集成测试 | JSONL/SQLite、真实子进程、Worker、WebSocket、MCP 测试 Server |
| Snapshot | 模型可见 Prompt、工具 Schema、拒绝文本和用户可见事件 |
| E2E | 从 UI/SDK 走真实组装，不直接调用内部服务 |
| Real API | DeepSeek 流式协议和能力探测；无 Key 时跳过 |
| 故障注入 | 崩溃、磁盘满、半写、断网、429、慢工具、审批超时 |

## 安全审查

建立威胁模型并至少覆盖：Prompt Injection、工具名伪造、Schema 绕过、目录穿越、符号链接、Shell 注入、环境变量泄漏、MCP 恶意 Server、SSRF、WebSocket 越权、Session 猜 ID、重放审批、TOCTOU、非幂等重试、跨 Session 数据泄漏、动态脚本逃逸和日志 Secret 泄漏。

## 数据和兼容性

- Session、Ontology 和协议各有独立单调格式版本。
- 升级先读旧格式到内存，再迁移到新文件；失败保留原件。
- 定义 Session/Spill/事实历史的保留和删除策略。
- 导出包含版本清单和校验哈希，导入前只验证不写入。
- Pre-release 可以拒绝旧格式，但错误必须给出备份和迁移指引。

## CI 门禁

每次提交运行 format check、lint、typecheck、unit、integration 和文档链接检查；主分支增加 coverage、Playwright、构建产物 smoke 和依赖审计。Real API、跨平台 Sandbox 和故障注入按计划任务或发布候选运行。

## 发布顺序

1. 生成 SBOM、第三方许可证和依赖锁定报告。
2. 构建 Runtime、Web 和 SDK，运行干净目录安装 smoke。
3. 用全新数据目录跑迁移和首次启动。
4. 用上一候选版本创建会话，再用当前版本验证兼容策略。
5. 运行安全清单、故障注入和恢复演练。
6. 发布候选，冻结 Schema；发现协议问题先修协议再发布正式版。

## 完成标准

所有 M4 场景可重复，关键失败有结构化诊断，进程关闭无孤儿 Worker/子进程，磁盘日志可恢复，Secret 扫描无泄漏，安全边界在用户文档中与实现一致。
