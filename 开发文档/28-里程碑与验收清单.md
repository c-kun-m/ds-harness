# 里程碑与验收清单

## 使用方法

不要按“写了多少文件”判断进度。每个里程碑必须从公开入口运行真实组装，产出可观察结果，并能在失败后恢复。以下清单全部通过后才进入下一阶段。

## M0：可测试内核

- [ ] 插件加载失败会回滚全部注册。
- [ ] 父子作用域互不污染，卸载无残留。
- [ ] Brand ID、JSON、错误和取消协议稳定。
- [ ] Session 事件连续、不可变，可从 JSON 重放。
- [ ] 非法事件、未知格式和损坏日志 fail closed。

交付演示：加载两个插件，创建内存 Session，追加并重放一个无模型 Turn。

## M1：单 Agent 闭环

- [ ] DeepSeek Adapter 能输出文本、reasoning、工具调用和 usage。
- [ ] 工具参数、审批、Guard、超时、post 和结果定稿全部生效。
- [ ] parallel 只重叠 body，结果保持模型顺序。
- [ ] followup、steer、inject 和 cancel 行为符合文档。
- [ ] Preset 决定每 Session 的工具和 Prompt。
- [ ] JSONL flush、resume、崩溃尾部恢复和 outcome unknown 通过。
- [ ] 长会话压缩后仍保留完整原日志。

交付演示：从 CLI 发起任务，模型读取文件、调用两个工具、回答；中途 steer；杀进程后恢复同一会话。

## M2：本体约束闭环

- [ ] 本体版本发布后不可变，事实按 Snapshot 查询。
- [ ] Action 和 Tool 映射在启动时完整验证。
- [ ] 候选工具由当前事实和身份生成。
- [ ] 执行前重新 Guard，审批不能覆盖本体拒绝。
- [ ] Policy Decision 包含规则 ID、本体版本和 factRevision。
- [ ] 业务写入使用 CAS/幂等键，Outbox 可重复投递。
- [ ] Plan DAG 可恢复，后置条件失败不会伪造成功。
- [ ] 补偿按逆依赖执行，补偿失败转人工 blocked。

交付演示：工单从 draft 到 submitted 的三节点计划；修改负责人使旧调用被 Guard 拒绝；模拟第二步失败并验证补偿和审计链。

## M3：长期任务与扩展

- [ ] Todo、Plan Mode、Goal 状态均可重放且职责不混淆。
- [ ] Goal 状态与 Round Driver 分离，恢复后默认 disarmed。
- [ ] Job owner 隔离、输出和取消正确。
- [ ] Spawn、Fork、one-shot、continuable 和 depth 限制正确。
- [ ] send_message 是下一 FIFO Turn，interrupt 只停止当前 Turn。
- [ ] Workflow 有 Worker、配额、取消和事件审计。
- [ ] Skill 目录与 Body 延迟加载，来源和信任可见。
- [ ] MCP 工具断线撤销、重连恢复，调用仍经过本体 Guard。

交付演示：父 Agent 启动两个子 Agent 和一个 MCP 工具，后台运行时继续本地工作，最后汇总；任一越权或断线都不会旁路策略。

## M4：产品化

- [ ] JSON-RPC 方法和通知有 Schema、cursor、背压和授权。
- [ ] SDK 子进程关闭无孤儿进程，run 边界描述准确。
- [ ] ACP 只暴露声明支持的能力。
- [ ] Web 重连后 Snapshot + 增量一致，不重复事件。
- [ ] 本体决策、DAG、工具、事实和补偿可以互相跳转。
- [ ] Unit、property、integration、snapshot、E2E 和故障注入通过。
- [ ] Threat Model、Secret 扫描、SBOM、数据保留和迁移策略完成。

交付演示：全新环境安装后，从 Web 创建会话、审批受控 Action、观察本体计划、恢复断线、导出审计包，再由 SDK 运行同一能力。

## 手写开发节奏

每个模块按“类型和状态机 → 假实现测试 → 真实 Provider → 公开入口集成 → 故障测试 → 文档”六步完成。不要先写页面再补事件，不要先接真实模型再补脚本化 Adapter，也不要在没有幂等和恢复语义时开放自动续跑。

## 暂停并重新设计的信号

- 为了加功能必须直接修改 Agent Loop，而已有扩展点理论上应能承载。
- 同一事实同时由 Session、SQLite Projection 和业务表各自修改。
- 工具隐藏和执行拒绝来自两套不同规则。
- 模型输出直接改变事实或计划状态，没有结构化验证。
- 进程崩溃后无法判断一个副作用是否发生。
- 子 Agent、Workflow 或 MCP 能绕过 Permission/Guard。
- UI 需要读取内部对象而不是公开投影。

出现任一项时先回到对应模块修正协议，再继续编码。
