# 本体约束 Agent Runtime 开发文档

这套文档把 DeepSeek Harness 当前源码中的可复用设计，整理成一条适合单人手写实现的开发路线。目标不是复制 DSH 的全部产品，而是先做出一个可运行、可恢复、可审计，并由本体策略确定性约束工具选择和执行的 Agent Runtime。

## 阅读和开发规则

1. 严格按编号开发；后一个模块只依赖已经完成的前置模块。
2. 每完成一个模块，先通过该文件的验收项和测试，再进入下一份文件。
3. 先完成单进程、单工作区、单模型的纵向闭环，再增加多 Agent、MCP 和 Web 产品能力。
4. 会进入模型请求的内容必须写入会话事件日志；任何业务动作都必须经过工具执行管线和本体策略，不能从 Controller 旁路调用。
5. 本体规则不是 Prompt 建议。候选工具、前置条件、执行许可、结果回写和补偿必须由确定性代码执行。
6. 本计划只新增开发文档，不修改 `deepseek-harness` 源码，也不处理仓库中已有的未跟踪 `.node-version`。

## 建议的第一次可运行演示

完成 03 至 08 后，先跑一个只含 `read_text` 和 `echo` 的内存会话：用户输入触发模型调用，模型调用工具，工具结果写入日志，模型输出最终答案，Turn 结束。完成 13 至 15 后，把同一演示改为只有满足本体前置条件时才向模型暴露 `read_text`，并在执行后写入一条事实变更和决策审计事件。
