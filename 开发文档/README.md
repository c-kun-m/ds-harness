# DeepSeek Harness 核心复刻与本体 Agent Runtime 课程

这套文档不是“照着几段示例代码做一个能跑的玩具”，而是一条从源码、行为契约、失败路径和测试出发，逐层复刻 DeepSeek Harness 核心，再在其上实现本体约束能力的学习路线。

你最终要获得两种能力：

1. 不依赖复制粘贴，能够解释并实现 Cordis/DSH 的生命周期、作用域、会话、模型、工具和 Agent Loop 核心；
2. 能够判断哪些能力来自上游 Harness，哪些是本项目新增的本体规划、策略、回写与补偿，避免把二者混成一个不可验证的大模块。

不要用 `main` 分支最新代码偷偷替代这个基线。以后升级时，先新建一份差异审计，再修改课程结论。

## 课程的三层边界

```text
K00–K13  插件内核层
           Cordis 生命周期、Effect、Fiber、Context、Service、Event、Scope
                  ↓
R04–R12  Agent Runtime 主链路
           类型 → Session → LLM → Tools → Agent Loop → Prompt → 安全 → 恢复 → 压缩
                  ↓
R13–R28  领域扩展与产品层
           本体策略 → Todo/Plan/Goal/Jobs/Subagent/Workflow/Skills/MCP → API/Web/发布
```

- 插件内核层追求关键可观察行为等价，不以“最少代码”为验收标准。
- Agent Runtime 主链路优先复刻上游核心合同，可以删减产品表面，但删减必须显式记录。
- 本体层是本项目原创扩展。它借用同一生命周期、事件日志和工具管线，但不能伪称为 DSH 原有能力。

## 学习规则

每一课都按同一种顺序学习：

1. 先读“问题”和“功能合同”，不知道源码怎么写也要先尝试设计；
2. 画出状态、所有权和异步边界，不从类名开始设计；
3. 只按“实现任务”写自己的代码，课程不会先给最终实现；
4. 先运行本课黑盒测试，再读固定版本上游源码；
5. 对照失败路径修正自己的实现，不以通过一个快乐路径测试为完成；
6. 用自己的话回答课末复盘问题，并记录与上游不同的取舍。

完整规则见 [课程使用说明与验收标准](课程使用说明与验收标准.md)，文件级入口见 [固定版本源码索引](固定版本源码索引.md)。

## “复刻完成”的定义

一个模块不能因为 API 名称相似或演示能跑就标记完成。至少需要同时满足：

- 正常路径、边界值和输入校验与课程合同一致；
- 失败时不遗留注册、子任务、监听器、文件句柄或未观察 Promise；
- 取消、并发、重复调用和重入下仍能到达稳定终态；
- disposer 只能撤销自己拥有的精确对象，旧句柄不能删掉新实例；
- 状态、事件顺序和错误类别可以被黑盒测试观察；
- 对照固定上游测试形成“通过 / 有意差异 / 未实现”的差异账本；
- 能解释实现为什么正确，而不是只说“测试绿了”。

如果删减了 HMR、异步生成器 Effect、冷恢复或某个事件模式，必须把它写进差异账本；不能继续称为该部分的完整复刻。

## 当前代码的定位

`packages/kernel/src/effect-stack.ts` 是课程早期练习，不是 Cordis Effect/Fiber 的完整实现。它可以保留，用于证明 LIFO 和幂等释放；进入 K04 前必须另建正式的生命周期模型，不能继续给这个类堆叠所有职责。

## 推荐的第一次完整演示

完成 K00–K13 和 04–08 后，演示应包含：插件依赖一个服务并注册工具；服务消失时插件自动卸载；服务恢复时插件重新激活；一次模型 Turn 发起并行安全与独占工具调用；结果按模型顺序写入 Session；中途取消后所有 Effect、工具任务和轮次事件都达到稳定终态。只有 `echo` 成功返回不算完整演示。
