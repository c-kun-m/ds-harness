## 1. 阅读纪律

推荐顺序：README/架构说明 → 公共类型 → 主实现 → invariant → 测试。先理解可观察合同，再看内部技巧。

本地链接方便直接阅读；提交升级后行号可能变化，因此课程不把行号当永久身份。需要验证基线时运行：

```powershell
git -C deepseek-harness rev-parse HEAD
git -C deepseek-harness status --short
```

预期第一条输出固定提交，第二条为空。不要修改被忽略的上游目录来“让参考实现符合自己的代码”。

## 7. 本体扩展没有上游实现

13–15 的本体模型、动作映射、策略判定、事实回写与补偿不是 DeepSeek Harness 当前源码的能力。参考上游时只能复用：

- Session 的仅追加审计和投影；
- Tools 的可见性、pre-execute、单调 Guard、执行和结果阶段；
- Agent Loop 的 Step/Turn 边界；
- Scope/Effect 的生命周期；
- Plan/Goal 的状态与调度分离思路。

不要把 MCP memory 示例的简单图结构当成完整本体规划器，也不要把 Prompt 中的规则当成确定性策略。
